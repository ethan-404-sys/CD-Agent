## 来源如何成为变化候选

S1_03、S1_02：SAM3 building，512不重叠平铺、像素>.85、实例分数≥.3/.2。
已有显式图像缓存 conf=.1 可复用。sam3_soft 只含分数≥.3，绝不用于.2；
S1主基准预先固定.2，.3作为单独敏感性结果，不能按结果挑有利基准。

S2：house/roof/factory/shed，各分数≥.5；每期合并这四个词的原始实例后匹配。
S5：起点中验证器明确答yes的所有原始组件作正示例框，不取真值组件、不截种子数。
新建种子在T2、拆除在T1、C0两期各作参考。参考期直接同图几何提示；对另一日期
用已实现的参考/查询拼图，只取查询半幅作为存在性对照。匹配所有同来源原始实例后
按方向取 appeared/disappeared。无yes种子时S5为空。两期拼图缩放可能损失分辨率，
本轮未验证真实影响。

S1/S2/S5均复用 instances.match(overlap=.25, mode=overlap)，单实例被另一日期
任一实例覆盖自身≥25%即存在；先匹配再扣起点，不用两期并集异或冒充实例匹配。

S3/S4复用 DynamicEarth SAM自动提议；DINOv2区域均值（现有双线性特征汇聚）
差异=1-cosine。S3先筛原提议面积>图像10%，S4不设面积限制。为约束建筑与方向，
用SegEarth building-vs-background概率>.5的两期增减作门控：T2增为新建、T1减为
拆除，C0二者并。门控不是标签；它引入的遗漏计入实际召回。DINO分数在完整原
SAM区域上计算，随后裁门控和起点。两来源分别在每个数据集×方向扫描0–2、步长
.05，用起点+来源累计像素F1最高的门限，并列取小；保留完整扫描，不声称泛化收益。

所有来源扣起点后取自身并集的8连通组件，作为返回和ask单位。不同来源之间不做
隐式去重；S1+Sx组合池显式重新连通后点数、核验，避免重复像素算成独立收益。

## 统计与判断

漏检=GT−起点。像素召回/精确率都按来源并集，不重复计像素。组件召回用每个
原漏检8组件被候选并集覆盖≥50%，不混用单候选IoU。边际像素/组件召回以原漏检
为分母；残余像素与组件召回先扣S1像素、重新连通，分母为剩余漏检。原组件新增
命中数另报，避免重新连通碎片改变分母后仍称同一指标。零分母写null/—。

上限参照固定为：起点不动，候选并集重新8连通，用GT选TP>FP的整组件加入。
只用S1与全部来源各报一次。平手不留，不允许按真值像素裁候选。该选择参照不是
任意子集数学最优F1；全部来源连接起来可能合并S1组件，可能降低这一参照值。

按末尾补充，取消旧5个百分点门槛。报告新增TP、S1后剩余漏检召回、涉及图数、
前5图与占比、前2图占比。验证器分别问Sx和S1+Sx，给出相对起点、相对S1的单
来源差，以及组合池相对已验证S1的净ΔF1。只有新增TP且组合净ΔF1>0才考虑
收录；≤2张贡献图或前2图≥80%标“集中、单列”，80%是可读性诊断标记，不是
Ethan指定的统计显著性门槛。其余来源仍须列出证据，不能把尚未ask写成失败。

原第12项边际最高1–2个来源标优先；补充要求逐来源净F1，因此费用同时列全部
S2–S5的单来源与S1组合池。Claude可先问优先池，再补其余池，不会自动调用。
配额建议总预算32，按开发集像素精确率最高平均数法分配，各来源不超过候选/图
p95；S1_03为敏感性不重复配额。无新增、已知净增益不为正或过度集中者不分配；
尚未核验的建议标provisional，ask完成后更新。精确率用于分配，新增召回与集中度同时展示；
未经开发结果时不填建议数字。该建议尚未做固定配额消融，不作为已验证最优值。

## 运行、I/O与费用

`fixed/generate/baseline`支持`--shard/--shards --resume`，完成图原子保存；生成
独立worker按图缓存。统计门限需看完整开发组，由CPU作业运行；每完成一组保存
报告，可`--group`分别运行。ask单池单作业，用`--concurrency`控制线程，不分片。
本地读写复用io_retry三次尝试、临时文件replace；I/O重试不包裹成功的模型/API调用。

`estimate --whu-fixed`先点WHU固定组件；`statistics`点来源与组合池。每组件一
请求，按已有开发ledger中cost_cny/有价格请求数估算；WHU尚无开发ledger时借
SECOND开发同卡单价并明确标记。不读取报告集补数。单价不等于实际逐请求上界。

ask仅显式子命令触发，要求已保存对应费用估计，支持`--max-cost-cny`及单请求
预留`--request-cost-cny`（默认.02元）。预算不足不发下一请求。成本和成功答案
逐请求原子保存，续跑跳过已有uid；在途成功答案全部收回。429/403/402/欠费
通过f37_corr strict_stop在重试前写STOP；其他请求失败也暂停池，不无限重试。
STOP需先解决原因，再显式`--clear-stop --resume`，已花费用不会清零。
实际单请求超预留会停止，已在途请求无法撤销；预算是客户端保守预留约束，不是
服务端计费承诺。当前只运行假后端测试，未验证真实服务及模型。
