CV Learning · Ethan 的任务设置方案 · 2026-10-29

变化检测智能体：能力与任务设置

研究方向是“变化检测 + 变化检测智能体”，开放词汇变化检测是其中一个任务。任务围绕两件事来设：变化检测流程中存在哪些问题，以及 Agent 解决这些问题时需要具备哪些能力。参照师兄的做法：灾害智能体按灾害的四个特点建任务，另一位师兄按增、删、改、查建任务。

灰底的“评审建议”是 Claude 的补充，不属于原方案。

01全流程：变化检测在哪里出问题

步骤 1 · 输入T1 / T2 两期影像可附带类别文本或需求文本
→
步骤 2 · 检测变化检测器输出变化掩码 change mask
→
步骤 3 · 存在的问题
误检：报了变化，其实没变 漏检：真实变化没报出来 掩码边界质量差
引入 Agent 之后读图理解 → 判断是否变化 → 定位区域 → 调度工具修改掩码误检场景看检测结果之内，漏检场景看检测结果之外

02Agent 需要的四种能力

能力 1

读图

同时理解遥感影像和文本，能在图像中找出文本指定的类别。

能力 2

判断

准确识别某区域从 T1 到 T2 是否发生了指定的变化，即“判断器”。

误检判断检测结果之内的区域漏检判断检测结果之外的区域
能力 3

定位

确认发生变化后，给出该区域的位置（点或框）。

误检检测结果之内漏检检测结果之外
能力 4

工具调度

和定位一起用：定位后选择合适的工具、给出合适的提示，交互式地完善掩码。

评审建议漏检场景在判断之前还需要一步“搜索”，即提出该去看哪里；exp8 的经验是难点主要在这里。误检本身已经是掩码，删除时通常不需要定位。工具调度应包含何时停止、何时回滚。

03能力与任务的对应

任务分两大类：第一大类对应单项能力，是端到端系统中某个模块的小任务；第二大类是端到端的完整任务，同时用到多种能力。

任务读图判断定位工具调度状态
第一大类 · 模块任务
1.1 遥感图像理解待定
1.2 变化判断先做，数据集 v0
1.3 定位基于 v0
1.4 工具调度可能与 1.3 合并
第二大类 · 端到端任务
2.1 给定类别即 OVCD
2.2 给定示例—
2.3 给定自然语言要求—

实心点：主要考察的能力；空心圈：会用到但不是考察重点。

04第一大类：模块任务

任务 1.1 · 读图

遥感图像理解

待定
设想
给定类别集合，让 MLLM 输出两期对象的类别。
目的
检验 MLLM 能否认出影像里的地物，以及文本对应的类别。

评审建议做成区域级：给一个区域，分别问 T1、T2 的类别。SECOND 的两期语义图可直接当真值，零标注；也可以和 1.2 共用数据。

任务 1.2 · 判断

变化判断：数据集 v0

先做
数据
SECOND 的 building 类，单独抽成一个集合：T1、T2、T1 语义、T2 语义、building 变化掩码。挑 250 张作为初始开发集 v0，之后需要再扩。
标注
检出的真实变化漏检误检三种颜色，以 GT 为准。
审核页
抽几个典型例子，展示全景和近景。
要想清楚
候选怎样构造，才能把想让 MLLM 区分的变化区域分出来：给 MLLM 看的图应该是什么形状、什么大小。
划分
训练集、验证集、测试集。
目的
得到一个能识别变化的判断器。

评审建议先定用哪个检测器（若在 SECOND 上训练过，250 张不能在它的训练集里）。负样本要包括没变化的建筑。候选分两档：v0-oracle 用 GT 推出的区域，v0-real 用实际能得到的候选，两者的差距本身就是结论。按图像划分，例如 150/50/50。exp6l 中 Qwen3.5-4B 的同类判断 AP 只有 0.071，预期要放低。

任务 1.3 · 定位

给出点或框，让 SAM 分出目标

基于 v0
设定
在 v0 中，已知某个 building 是漏检或误检。
输出
MLLM 输出点或框的坐标，输入给 SAM、SAM3 等工具，把这个 building 分出来。
效果
已知是漏检还是误检，就知道分出来的目标该加上还是删除；加上或删除之后，F1 会变化。
待定
要不要人工确定最佳点或框，作为 golden 数据？还是点只要落在 building 形状内就行？

评审建议不需要人工标。GT 外接框就是 golden 框，用它提示 SAM 的 IoU 是上界。点位影响有多大，可以自动比较中心点、随机内部点和边缘点来实测。评测看三项：命中率、SAM 结果与 GT 的 IoU、F1 变化。SAM 在哪一期上分（新建用 T2，拆除用 T1）也应由 MLLM 决定。

任务 1.4 · 工具调度

有限预算内取得最大 F1 收益

可能与 1.3 合并
设定
同样已知漏检和误检。
目标
在有限的预算内执行动作，取得最大的 F1 收益。

评审建议每张图最多 k 步，记录每一步后的 F1，画 F1–步数曲线。要注明这是“已知错误类型”的设定；端到端任务里 Agent 并不知道哪里是漏检，两者的数字不能直接比。

05第二大类：端到端任务

任务 2.1

给定类别的变化检测

输入
T1、T2、类别文本
输出
该类别的变化掩码

评审建议就是 OVCD，沿用 DynamicEarth 的协议，可以和已有论文直接比。服务器上正在跑的 v0（LEVIR building）属于这一项。

任务 2.2

给定示例的变化检测

输入
T1、T2，以及一组变化示例
输出
与示例同类的变化掩码

评审建议查到的 OVCD 论文都没做过这种设定，可能是新意所在（推断，需专门检索确认）。要先定示例怎么给：几对、给裁剪还是给掩码。

任务 2.3

给定特定文本的变化检测

输入
T1、T2，以及一段自然语言要求
输出
符合要求的变化掩码

评审建议和指代变化检测（RCD）、QSCP、DVL-Bench 最接近。可以吸收昨天讨论的细粒度查询，例如“新建的建筑”“被拆除的建筑”。

06待定的问题

  1. 任务 1.1 的具体形式：输出对象类别，还是区域的两期类别？原方案待定
  2. 数据集 v0 的候选形状和大小：给 MLLM 看的图长什么样？原方案待定
  3. 定位任务是否需要人工 golden 点或框？原方案待定 · 建议不需要
  4. 任务 1.3 和 1.4 是否合并？原方案待定
  5. 数据集 v0 用哪个检测器，250 张从 SECOND 的哪一部分取？评审补充
