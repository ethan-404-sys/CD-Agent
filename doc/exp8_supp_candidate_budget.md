# 任务：实验 8 补充，候选预算曲线（候选数 vs 召回 vs oracle ΔF1）

给服务器上的 Claude。本文是 `doc/exp8_object_pool.md` 的补充，**依赖 exp8 第 1 步的跨来源去重代码和对象级候选池**，与 exp8 第 2–5 步互不依赖。前置结果见 `results/exp4_recall_candidates.md`（或 summary 中的实验 4）、`results/exp5c_end_to_end.md`、exp8 第 1 步结果。

本实验**不训练、不调用 MLLM**，只做统计和画图。

**执行顺序**：第 1 → 2 步；第 3 步要用第 4 步的 r1 排序（r1 不需训练，可先实现）；然后第 4 → 5 → 6 步。

**算力门槛**：所有旋钮只在**已缓存的来源输出**上做后过滤（按已保存的分数、面积等筛选）。凡需要重跑 SAM3 或 AnyChange 的设置（包括补算 C、SYSU 的 H1，或第 5 步中某个组合），先停下，按数据集和划分列出预计 GPU 小时报给 Ethan，由他决定是否运行。

## 为什么做

1. **我们需要一个量化依据来决定"候选给多少"。** 候选多，召回高，但后续判断（V1、SAM3、MLLM）成本高、负例多；候选少，召回低。目前四源并集覆盖约 52% 漏检（此数请注明出处和口径；exp8 第 1 步报告的是 U5 覆盖无信号漏检像素 63%、U0 为 69%，口径不同，本实验统一重算），但每图候选数、来源之间的重复、去重的效果都没有量化。目标检测（Hosang 等 TPAMI 2015 的 AR 曲线）和医学 CAD（LUNA16 的 FROC）都是先画"召回 vs 每图候选数"曲线，再在验证集上选工作点。
2. **只看召回会退化。** 把检测器掩码之外的区域整个当成一个候选，召回就是 100%、候选数为 1，但 F1 会大跌。所以本实验的召回必须带质量条件（对象级 IoU），并以 **oracle ΔF1** 作为主指标。
3. **只看像素召回会鼓励碎候选。** 碎候选会直接拖累后续 MLLM 判断，所以对象召回和像素召回都要报告，并加碎片指标。
4. **F1 的边际规则。** 当前 F1 记为 F。往结果中加入一块区域，其中新增真阳性像素 a、误检像素 b：当且仅当 a/(a+b) > F/2 时 F1 上升（推导：F1 = 2TP/(2TP+FP+FN)，加入后分子 +2a、分母 +a+b）。删除一块预测区域时方向相反：a/(a+b) < F/2 时 F1 上升。SECOND（F = 74.17）门槛约 37.1%，SYSU（F = 84.58）约 42.3%，与 6b 测到的 37% 一致。因此**以 F1 为目标时，候选的理想排序分数是它在检测器掩码之外部分的像素精度**，oracle 也按这个规则定义（见下）。

## 规则
- 不修改官方影像和真值，不训练任何模型，不调用外部 API 或 MLLM。
- 曲线、工作点、排序规则全部在**验证部分**（exp8 第 0 步确定的训练池验证划分）上画和选；测试集只对最后冻结的 2–3 个工作点各评一次。
- 每一步先报告数字再进入下一步。
- 新代码放 `code/probe/exp8s_*.py`，复用 exp8 第 1 步的去重代码，不改动它的默认行为。

## 数据集与来源
- **必做：SECOND、SYSU-CD**（补漏的主战场）。LEVIR-CD、WHU-CD：如果 exp8 第 1 步已经生成了它们的候选，顺带跑第 1、2 步；没有就跳过，不专门生成。LEVIR / WHU 只在测试集上做**描述性统计，不选工作点**（WHU 没有 val）。
- 来源：B（SAM3 六类做差）、G（检测器低阈值）、H1（AnyChange）、C（建筑实例差，C1/C2 合称 C，内部先去重）。**这里四个来源都要算**，包括 exp8 第 1 步没用的 C 和 SYSU 上的 H1，因为本实验的目的就是给来源取舍提供依据。pred 属于去误检一侧，不纳入。
- 每个候选只看**检测器 0.5 掩码之外的部分**（"新增像素"）；新增像素 < 20 像素的候选直接丢弃，并报告丢弃数量。

## 定义

**计数单位**：exp8 第 1 步跨来源去重后的对象。**不计 SLIC 切块。** 每图候选数报告均值和 P90。另外把 **U5**（exp8 第 1 步冻结的混合单元：大对象按 SAM 对象级划分再拆，SECOND ×4、SYSU ×4）作为一条对照线：SECOND 上不切分对象的 oracle 上界只有 +4.69，U5 为 +7.19，只用不切分对象会压低曲线天花板。

**漏检对象**：真值内、检测器 0.5 掩码外的连通域（沿用 exp4 的定义和最小面积）；同时单独报告 exp4 的"无信号漏检"子集。

每个曲线点报告以下指标：

| 记号 | 指标 | 说明 |
|---|---|---|
| R_obj@τ | 对象召回 | 漏检对象 m 被命中，当且仅当存在候选 c 使 IoU(c 的新增像素, m) ≥ τ。τ = 0.3、0.5 两档，另报 τ 从 0.3 到 0.7（步长 0.1）的平均 AR_obj |
| R_pix | 像素召回 | 候选新增像素并集覆盖漏检像素的比例。**只作参考**，会被大候选刷高 |
| ΔF1_oracle | oracle ΔF1（主指标） | 完美判断、候选整块并入：只并入新增像素精度 a/(a+b) > F/2 的候选（F 为验证部分检测器的 F1）。同时报告 exp8 口径（真值占比 ≥ 50% 才并入）的数值，便于和 exp8 对照 |
| Frag | 碎片程度 | 每个被命中的漏检对象平均与几个候选重叠（重叠 ≥ 10% 的候选计数）；以及面积 < 100 像素的候选占比 |
| Pos% | 正例率 | 新增像素精度 > F/2 的候选占比，即"值得并入"的候选比例，决定后续判断的难度 |

横轴默认是**每图候选数（去重后）**。另画一张横轴为"候选新增像素总面积占图像比例"的版本，用来识别靠大候选刷召回的情况。

## 第 1 步：单来源曲线
1. 为每个来源确定**一个**连续旋钮，并写明取值：
   - G：概率阈值，至少 {0.05, 0.1, 0.2, 0.3, 0.4}；
   - B：SAM3 类别置信度阈值或最小面积（选一个，写明理由），至少 5 档；
   - H1：AnyChange 变化置信度的阈值或每图 top-k，至少 5 档；
   - C：实例差的匹配阈值或最小面积，至少 5 档。
2. 每个来源固定其他设置、扫这个旋钮，来源内部先按 exp8 的去重规则去重，得到一条曲线。
3. 输出：四个来源画在同一组坐标轴上，纵轴分别为 R_obj@0.5 和 ΔF1_oracle 两张图。表中列出每档的全部指标。

## 第 2 步：按来源逐个累加的阶梯线
1. 每个来源取 5c 的默认设置（没有默认的取第 1 步中 ΔF1_oracle 最高的一档）。
2. 从 ΔF1_oracle 最高的单个来源开始，每次加入"每多一个候选带来的 ΔF1_oracle 增量最大"的来源，得到 1→2→3→4 个来源共 4 个点。
3. 同一组点分别按**原始并集（不去重）**和**去重后**计数，画两条阶梯线。两条线最右端的点即"原始四源并集"和"去重后四源并集"，用箭头连接。
4. 配一张来源表：每个来源的候选数、独有命中（只有它命中的漏检对象数和像素数）、与其他来源的重复率（被去重合并掉的比例）、对 ΔF1_oracle 的独有贡献（去掉它之后 ΔF1_oracle 下降多少）。

## 第 3 步：去重方式对比
四源并集上比较至少两种去重方式，每种单独成线（**不同方式的点不要连成一条线**）：
- D1：exp8 第 1 步的规则（IoU ≥ 0.5 或小者 ≥ 80% 落入大者，取并集）；
- D2：同样的匹配条件，但不取并集，保留组内面积最小的那个候选（避免合并后变大、变不纯）；
- D3（可选）：IoU 阈值改为 0.3 的 D1。

候选数靠第 4 步的排序规则 r1 截取每图前 K 个来控制（K = 1, 2, 3, 5, 8, 12, 20, 全部）。报告每种方式在同一 K 下的 R_obj@0.5、ΔF1_oracle、Frag，回答"去重是否误伤召回"：理想的去重应让点向左平移而不下降。

## 第 4 步：不训练的统一排序规则
在 D1 去重后的四源并集上，用以下排序规则给每图候选排序，截取前 K 个（K 同第 3 步），每条规则一条线：
- r0（上界）：按真实新增像素精度降序。只作 oracle 参照；
- r1：来源一致数降序，平局按新增像素面积升序；
- r2：候选新增像素内的检测器平均概率降序；
- r3：第 2 步得到的来源优先级（同来源内按该来源自身的分数）；
- r4：有 AnyChange 分数的候选用其分数，其余按 r2，并写明如何把两种分数放到同一尺度（例如各自转成图内排名百分位）。

另做一个**全局阈值**版本：不按每图 K 截取，而是在整个验证部分按分数取前 N 个，扫 N，用"平均每图候选数"作横轴。比较每图 top-K 和全局 top-N 哪种更好。

每条规则同时报告：在 Pos% 意义下的 AP（按排序检索"值得并入"的候选），以及与 r0 曲线的差距。**这一步也回答：V1 以外，有没有不训练的分数能把有用的候选排在前面。**

## 第 5 步：帕累托前沿与工作点
1. 对四个来源的旋钮做粗网格（每个来源取 3 档，共 81 种组合），每种组合按 D1 去重后得到一个点。在每个横坐标处取最高的点连成上包络，即帕累托前沿。纵轴分别用 R_obj@0.5 和 ΔF1_oracle。
2. 把第 4 步的各排序规则曲线和前沿画在同一张图上。前沿与排序曲线之间的差距，就是"排序不够好"损失的部分。
3. 第 5 步 81 种组合 = 四个来源各取 3 档（3⁴）。只对能从缓存后过滤的组合计算；需要重跑的组合按“算力门槛”先报耗时。
4. 在验证部分选 2–3 个工作点（例如每图 3、8、20 个候选），写明对应的来源设置、去重方式和排序规则，冻结后在测试集上各评一次，报告全部指标。
5. **验证 → 测试的迁移**：SECOND 验证部分用交叉拟合检测器、测试用官方权重，G 来源直接依赖检测器概率。对每个冻结工作点，并列报告验证与测试的每图候选数、R_obj@0.5、ΔF1_oracle，说明偏移有多大。
6. 按 V2 单次耗时估算每个工作点全测试集交给 MLLM 需要的 GPU 小时（与 exp8 第 3 步的级联统计放在一起看）。

## 第 6 步：真实评分器下的召回视角（回答“漏检率降了多少、F1 有没有掉”）
Ethan 的验收口径：**降低漏检率，同时保住 F1**；ΔF1 ≈ 0 但几乎没补像素不算数。前 5 步都是 oracle，本步换成真实评分器。
1. 评分器：exp8 第 3 步已冻结的 V1（full / clean）和检测器概率规则，**不重训**；单元用第 5 步冻结的工作点，另加 exp8 第 3 步的原设置作对照。
2. 每个方案报告像素级 精度 / 召回 / 漏检率（FN / 真值像素），相对检测器的 Δ召回、Δ漏检率、Δ精度、ΔF1、ΔIoU；以及对象级召回（真值对象被覆盖 ≥ 50%）和新增误检对象数 / 图。
3. 在验证部分扫评分器阈值，画“像素召回 vs 像素 F1”曲线，标出 pixel、recall80 两个冻结点；测试集只画冻结点。
4. 给出 **ΔF1 ≥ −0.3 条件下，验证部分能达到的最大召回提升**及对应阈值；冻结后在测试集评一次，报告测试的 Δ召回、Δ漏检率和 ΔF1。

## 判断问题（写进结果文件）
1. 四个来源各自的召回–候选数曲线什么形状？哪个来源性价比最高，哪个几乎没有独有贡献？
2. 去重后候选数降了多少，召回和 ΔF1_oracle 损失多少？D1 与 D2 哪个更好？
3. 要拿到四源并集 ΔF1_oracle 的 80%、90%，每图分别需要多少候选？
4. 不训练的排序规则中哪个最接近 r0？它与 r0 的差距有多大？每图 top-K 与全局 top-N 哪个更好？
5. 以对象召回和像素召回分别看，结论是否一致？碎片指标在哪些设置下明显变差？
6. SECOND 与 SYSU 的曲线形状是否一致？不一致时更像是数据问题（标签口径）还是候选来源的问题？
7. 建议：后续流水线用哪些来源、哪种去重、哪个排序、每图多少候选？
8. 真实评分器下，在 ΔF1 ≥ −0.3 时漏检率最多能降多少？验证到测试是否保持？
