## 目的（Ethan 2026-10-28）
**第一版只为一件事：把整个系统的流水线跑通**，也就是流程图 A 节的主流程：

输入 → 口径卡 → 初始化 M0 → 建立状态 → Agent 循环（阶段 A 去误检、B 补漏、C 修边界）→ 输出 M_final 与轨迹 → 评测

- **不对收益设任何门槛。** 某一步没有提升、甚至变差，都如实记录，然后继续往下做，不要停下来等 Ethan。设计文档里 M2 的“去留判断”在本实验中只记录、不拦截。
- **先挑一条路走到底**：用第 1 轮的固定配置把 M0 到 M4 全部做完。
- **然后换一种配置再走一轮，如此反复。** 每一轮都是完整的 M0 到 M4。

## 每轮的步骤：M0 到 M4

### M0：初始化与复现
- 用 DynamicEarth 官方代码和评测脚本，在 LEVIR 测试集上跑 M-C-I，记录 F1^c、IoU^c、P、R。
- 与原文的 53.6 / 36.6 比较。差距超过 2 个点就查原因并记录，但**不阻塞**：用你跑出来的 M0 继续往下做。
- 保存每张图的 M0 和分数图。M-C-I 对每个 SAM 掩码给出的变化分数和类别得分要一并保存，T7 会用到。
- 同时跑 I-M-C（APE-DINO），只作为对比行，不作为第 1 轮的初始化。

### M1：初始化输出的错误分析
在验证集的 M0 上统计，并在测试集上描述：
- 整目标漏检率：真值连通域与 M0 的 IoU < 0.1 的比例；
- 整目标误检率：M0 连通域与真值的 IoU < 0.1 的比例；
- 误检像素和漏检像素各占多少；
- 漏检里有多少完全孤立（沿用 `results/miss_share.md` 的 ② 定义）。

这些数字用来决定阶段 A 和阶段 B 各分多少预算。

### M2：阶段 A，去误检
- 待查项：M0 的每个连通域，按可疑程度排序。可疑程度的定义由你定，例如 M-C-I 的变化分数、类别得分、面积。
- 每个待查项：T2 放大 → T3 核实 → 判否则 T4 删除。
- T3 的提示：系统提示里放 building 的口径卡，每次请求放 T1、T2 近景，用红色轮廓标出连通域。回答是否、伪变化类型和一句理由。读数用 yes / no 词元概率。
- 口径卡（v0 固定）：
  - 算：新建、拆除、拆除后重建；
  - 不算：阴影、季节色调、配准错位造成的边缘响应、车辆和临时堆放、非建筑地物（道路、植被、裸地）的变化。
- 删除阈值在验证集上选。

### M3：阶段 B，补漏
- T7 找可疑区域，至少用下面两种来源中的一种，写明选了哪种、为什么：
  - M-C-I 中变化分数或类别得分接近阈值、但没进 M0 的 SAM 掩码；
  - SAM3 用文本 building 分别分割两期，两期不一致、且不在当前掩码里的区域。
- 每个可疑区域：T2 放大 → T3 核实 → 判是则 T5：MLLM 在放大图里画框，SAM 用这个框在 T1、T2 上各分割一次，取并集后加入掩码。
- 如果 Qwen3.5-4B 画不出可用的框，退回“直接用可疑区域本身的掩码”，并记录画框失败的比例。

### M4：阶段 C，修边界
- 对保留下来的每个连通域，用它的外接框或内部点提示 SAM 重新分割，替换原掩码。
- 如果替换后在验证集上变差，照样记录，并试一种更保守的做法，例如只在新旧掩码 IoU 高于某个值时才替换。

### 每轮的评测
- 在测试集上报告四个状态：M0、M0 + A、M0 + A + B、M0 + A + B + C。每个状态都报：
  - F1^c、IoU^c、P、R，按整个测试集累计；
  - 整目标漏检率、整目标误检率；
  - 逐图平均 F1；
  - MLLM 调用次数和耗时。
- 预算曲线：k = 10、20、50 下的 F1^c。
- 对比行：DynamicEarth M-C-I、I-M-C（本次复现），以及原文数字。

## 第 2 轮及以后
第 1 轮走完后，换一种配置再走一轮完整的 M0 到 M4。
- **每轮只改一个主要因素**，写明改了什么、为什么。候选：
  - 初始化换成 I-M-C（APE-DINO）或 ReA-OVCD；
  - T7 换一种来源；
  - 口径卡或提示的写法；
  - 阶段 A 的排序方式或阈值。
- **下一轮改什么，依据是上一轮验证集上的诊断，不能看测试集结果来挑。** 每轮的测试集只评一次。
- 换 MLLM 为 qwen3-vl-plus 需要调用接口，**先估费用报给 Ethan，确认后才能跑**。其他改动不需要等。
- 数据集和类别在本实验中不换。

## 资源
- 每轮开跑前估 GPU 小时：DynamicEarth 推理、SAM、SAM3、Qwen3.5-4B 调用分开估。
- 单轮超过 8 GPU 小时，或累计超过 30 GPU 小时，先停下报告。这是唯一需要停下的情况。
- 不调用外部接口，除非 Ethan 确认。

## 轨迹记录
每张图、每一步都写入轨迹 JSON：步骤编号、阶段、动作（T2–T6）、待查项编号和外接框、送给 MLLM 的图像路径、MLLM 的原始回答和 P(yes)、执行的掩码操作、操作前后这张图的 F1^c。

## 审核页：`results/ovcd_v0_review.html`
**风格**：参照 `doc/ovcd_agent_v0_pipeline.html`，可以直接复用它的 CSS 和页面结构：顶部标题与来源、分节字母编号、卡片网格、流程图写法、明暗主题。

**结构**：
1. **顶部**：
   - 轮次下拉菜单。每一轮的内容完全分开，切换下拉菜单只显示该轮，不混在一起。只做了一轮时，下拉菜单只有一项；
   - 当前所处的实验阶段，如“第 2 轮 · M3”；
   - 本轮配置表，并写明与上一轮相比改了什么。
2. **按实验路线逐节**，M0、M1、M2、M3、M4 各一节。每节固定四块：
   - **做了什么**：具体做法与参数；
   - **得到了什么结果**：能画图的都用图加解释，不要只有文字，也不要只有图。例如每个状态的 F1^c 柱状图、预算曲线、误检与漏检的构成图；
   - **遇到的关键问题**；
   - **下一步怎么做，为什么**。
3. **汇总**：本轮四个状态的总表和对比行。
4. **例子回放（每轮必须有）**：
   - 挑一张图，不论结果好坏，展示图像怎样一步步变化：T1、T2、真值、M0 → 阶段 A 后 → 阶段 B 后 → 阶段 C 后；
   - 每个状态都用同一视野，并在掩码上标出相对上一状态新增（绿）和删除（红）的部分，标出该图的 F1^c；
   - 列出这张图上 MLLM 的每次调用：送入的近景、回答、P(yes)、执行的动作。
   - 最好再挑一张效果变差的图，说明原因。
5. **轮次之间的比较**：只在不止一轮时出现，单独一节，用表和图对比各轮的测试集结果。

**图片**：放在 `figures/ovcd_v0/round_<n>/`，页面用相对路径引用，保证从仓库检出后直接用浏览器打开能看。
