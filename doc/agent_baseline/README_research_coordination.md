## 1. 研究定位（高于单项实验的判断）

研究目标不是尽快排齐论文表格，也不是单纯提升单个指标，而是让变化检测 Agent 在多类任务/限制条件中展现**真实的自主规划、工具调度、视觉示例利用、候选发现与结果修正**能力。现有任务体系及多数已有结果可作为研究基础；Harness 仍在演进，**不同任务可以保留当时表现可靠的 G1–G5 配置**。每行结果准确登记版本、split、重复次数和对照即可；**不要求为了统一版本而逐项重跑**。

对效果不佳的任务，先区分：A 实现/接口/数据问题（Bug）；B Toolbox 候选与感知能力瓶颈；C 验证器问题；D Agent 规划、推理、调度、结果整合、终止问题。结论应有具体轨迹、代码行为或消融支撑。修复 Bug 不应冒充算法贡献；有收益的工具/决策机制也不应在没有对照时直接称为 Agent 创新。

## 2. 当前四条优先主线

| 工作流 | 类型 | 目标和出口 |
|---|---|---|
| **Agent 行为轨迹分析** | **完成型** | 复用所有任务/配置的历史轨迹，完成冗余、过度调用、错误与盲信、答案状态与终止四大类逐事件统计和可复核样例；为每种根因提供证据；不要直接把相关性写为因果 |
| **Harness Debug / Gate6** | **完成型+发现即修** | 处理 view 原图/渲染坐标歧义、compare_features 分数统计、bad_args、mask/handle 状态与提交；小单测、冻结回放、必要开发集烟测，默认关闭确保兼容 |
| **T3 图像示例** | **自主迭代研究型** | 让图像示例真正影响候选发现、排序和变化事件判断；先沿已有 T3 路线（几何+DINOv2、成对验证、反例），失败后可依据真实瓶颈调技术路线，避免只在同一错误路线调阈值 |
| **多来源 `find_missed`** | **自主迭代研究型** | 在已有变化掩码之外主动发现**漏检 FN**，先做现有 S1–S5 开发集候选、互补性和核验成本分析；不能退化成已有低门限 SAM3 的包装，不能让隐藏规则直接改最终答案 |

另外，既已批准且有现成数据的 **T4.1 v3、xBD 小样本验证器实验**可照旧执行并汇报；不应挤占以上主线。其他历史任务先维持现有结果，除明确诊断需要不统一重跑。

> 术语：删除误检（FP）与补回漏检（FN）是两个不同能力；本阶段尤其关注后者，`find_missed` 是补漏（FN recovery）工具，而不是误检删除工具。

## 3. 自主循环与什么时候需要 Ethan

**完成型任务**：按照既定协议做好，运行验证，附结果路径和结论即可，不需要每一步重新请示。

**T3、find_missed**：服务器 GPT 不需要每轮向 Ethan 请示。按以下闭环自主推进：

1. 从真实失败/轨迹/候选分析提出可检验的具体假设，并预先写明成功/失败判断；
2. 优先离线与现有开发集、缓存、已归档回答；做小规模 pilot 而非直接报告集/测试集全量；
3. 记录每轮方法、配置/sha、数据清单、精度/召回/F1、成本、失败样例与机制解释；
4. 不达预期时排查 bug、测可达上限，再迭代；**连续未得到有效信号时主动换路线/参考已有论文与工具方法**，附来源、与已有实现的关键差异、最小验证实验；
5. 仅在开发集明确可行、定义和对照公平的情况下提出报告集方案；正式报告要冻结设计，并保留负结果；
6. 实在遇到技术瓶颈时汇总“为何不可行 + 已否定路线 + 下一可行选择”，不要无限重试近似相同方案。

自主权不等于无限额度。**Agent 作业并发最多 2 个；任一实验或同一研究迭代的累计预计费用将超过 ¥100，测试集运行，或需要更高资源/外部付费授权，应先问 Ethan；不得拆分实验绕过门槛。** 遵循原来的开发/报告/测试集隔离，禁止在报告集上回调策略。Git 不 force push，涉及共享工作树先检查状态，改动尽量小而可回滚。
