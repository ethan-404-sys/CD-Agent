开放词汇变化检测往哪扩展：更多类别，还是更细的类别

我们要决定 OVCD 的“开放”体现在哪一个维度上。一条路是横向扩展类别，每个类别作为一个单独的检测任务；另一条路是在已有类别内部纵向细分，例如把建筑变化分成新建、拆除、损毁等。两条路需要的数据、能讲的故事和风险都不一样。

00现状：OVCD 论文实际在测什么

DynamicEarth
建筑类 4 个数据集（LEVIR-CD、WHU-CD、S2Looking、BANDON），查询文本固定为 building；再加 SECOND 六类，按 OR 规则逐类构造真值。
后续论文
加入了 DSIFN、Hi-UCD mini（OpenDPR）、CLCD 耕地（Seg2Change、CogVis）、xBD（CogVis）。
变化定义
只问“这个类别有没有变化”，不区分方向。指代变化检测（RCD）只算新增方向；QSCP 支持 from→to 查询，但这两者都是在 SECOND 上做监督训练的。
空白
没有任何 OVCD 论文划分“见过”和“没见过”的类别，查询词基本等于数据集的类别名。在检索范围内，没有免训练方法处理过“新建的建筑”“被拆除的建筑”这类细粒度查询。

出处：仓库 results/survey_ovcd.md 第 1、2、6 节。

01两条路线

路线 A · 扩展类别

每个类别作为一个单独的检测任务

动机
DynamicEarth 的相关工作里写道：用户往往只关注特定类别的变化，例如城市扩张看建筑、农业保护看耕地、灾害监测看滑坡。
数据
收集现成的单类变化数据集，例如耕地 CLCD、滑坡 GVLM、灾损 xBD，加上已有的建筑和 SECOND 六类。基本不需要新标注。
对 Agent 的意义
每个任务配一张口径卡（什么算变化、什么不算），Agent 按口径核实。这一点能体现出来。
风险
  • 一个类别对应一个数据集，查询词和数据集一一对应，“开放”程度不强，更像是把几个单类基准拼在一起；
  • CLCD 和 xBD 已经有人在测，新意有限；
  • 单类数据集只标了本类，其他地物的变化在真值里算背景。各数据集的口径不一致，评测会被标注口径拖累。
路线 B · 细粒度类别

在已有类别内部再细分

动机
来自和师兄的讨论。以建筑为例，可以分成新建、拆除、原址重建、厂房或温室，以及灾害损毁等级。这对应师兄方案里 L2 的 1.1–1.5、4.3、8.4。
数据
一部分可以从现有标注直接派生：S2Looking 的新建和拆除分开标注，SECOND 有两期语义图，xBD 有 4 级损毁。用途类细分要新标注，可以用 OSM 标签做种子。
对 Agent 的意义
要回答“是不是新建的”“是不是被拆了”，必须对照两期、结合上下文推理，CLIP 式的单期识别器很难做到。这正是 MLLM 比现有免训练流程强的地方，Agent 故事更站得住。
风险
  • 评测协议要自己定：OR 规则不区分方向，需要新的协议；
  • 口径更难界定，例如扩张和新建的区别、原址重建在端点差分里看不到；
  • 和已有论文的数字不能直接比；
  • 超出派生范围的部分，标注成本高。

03和师兄方案的对应关系

师兄的方案是建一个全球多场景变化数据集，按四层正交组织。它和这两条路线并不冲突，而是分别对应其中不同的层：

L1 成因域 · 9 类≈ 路线 A 的类别维度

D1 城市建设、D4 农业、D8 灾害……每个成因域可以对应一个用户任务。

L2 变化类型 · 26 种≈ 路线 B 的细粒度维度

每种都写成“A→B”的语义转移，可以直接拿来当细粒度查询的词表，例如 1.1 建筑新建、1.2 建筑拆除。

L4 地物词表 · 12+2 类≈ 查询文本的词汇

决定 OVCD 的查询可以问什么地物；L3 场景只是 AOI 属性，不是类别。

区别在于时间尺度。师兄的方案要采 4000–8000 对、走完 5 个阶段，是长期的数据工作；我们现在要定的是近期的研究问题。比较现实的做法是：先用现有数据把方向验证出来，师兄的 L2 表作为细粒度词表的来源，等数据集建成后再作为最终的评测集。

04我的建议

主线走路线 B，从建筑做起；路线 A 只保留少量类别，用来检验泛化。

  • 理由：路线 A 的增量主要是“多测几个数据集”，已经有人在做，而且和 MLLM Agent 的关系不紧。路线 B 的查询需要对照两期做推理，现有免训练流程难以回答，正好是 Agent 的用武之地，也是检索范围内的空白。
  • 第一步不需要新标注：用 S2Looking 的新建和拆除标注、SECOND 的建筑方向和 from→to、xBD 的损毁等级，构造一个建筑细粒度派生集。查询例如“newly built buildings”“demolished buildings”“destroyed buildings”。基线可以用 DynamicEarth 加两期类别规则，例如新建 = T2 是建筑且 T1 不是。
  • 路线 A：挑 CLCD 耕地和一个滑坡集，作为泛化检验，不作为主贡献。
  • 和 v0 的衔接：服务器上的 v0 正在 LEVIR building 上跑通流程，这一步不受影响。跑通后，第二个任务可以直接换成 S2Looking 的“新建 / 拆除”。

这是我的判断，不是检索得出的结论。

05下午要和师兄定的几个问题

  1. 我们说的“开放词汇”，开放的是类别名，还是描述和转移（如“从耕地变成建筑”“被拆除的建筑”）？这决定了走 A 还是 B。
  2. 细粒度查询的评测协议怎么定：OR 规则不区分方向，方向和转移查询需要新协议。是否参照 RCD 和 QSCP 的定义？
  3. 建筑细分到哪一层就够写一篇：只做方向（新建、拆除），还是加上损毁等级和用途？
  4. 标注预算：派生集是否足够？什么时候需要人工标注，标多少？
  5. 和师兄数据集的关系：是否共用 L2 词表？他的数据集什么时候能有第一批可用的样本？
  6. 路线 A 保留哪几个类别作为泛化检验？
