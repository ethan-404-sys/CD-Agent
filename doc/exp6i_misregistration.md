# 任务：实验 6i，SECOND 两期影像的配准偏移有多严重

给服务器上的 Claude。前置结果见 `doc/exp6g_label_noise.md`、`audit/samples.json`、`results/exp6a_pool.md`、`results/exp6b_verifier.md`。本任务**不训练任何模型**，只估计偏移并统计。全部是 CPU 工作，V2 和 6f 优先。

## 为什么做
- 6g 审核中发现明显的两期错位：`test_857.png` 的切块 18（6g 网页第 11、291 号，S2，真值“没变”）只有 18 像素，两期整体错开约 10 像素，t1 红框里的暗角在 t2 中对应的是右侧的小建筑。人工审核时很容易误判为“变了”。
- 整条流水线都没有配准步骤：`common.py` 的 `load_rgb` 直接读原图，6a 候选、6b 特征、V2 裁块都假设两期逐像素对齐。
- SECOND 的真值是语义层面的，错位不算变化。所以错位切块是“难负样本”。小切块在 6b 中按同一掩膜坐标池化 t1、t2 特征，偏移 10 像素时两边平均的是不同地物；V2 的近景框最小只有 64 像素，偏移占比更大。
- 待验证的假设：(1) 相当一部分切块落在偏移 > 3 像素的区域；(2) 偏移以局部为主（高楼视差），整图平移解释不了；(3) 偏移集中在 C1 来源（单期 SAM 实例找不到 IoU ≥ 0.5 的匹配）、小切块和 S3 高分负例中；(4) V1 在大偏移切块上的 AUC 明显更低。

## 规则
- 不修改任何官方影像和真值文件，不把配准后的影像写回数据集目录。
- 偏移估计只用两期 RGB 影像。真值变化图只用于**排除真变化区域**（真变化会破坏相关性），不用于估计偏移本身。
- 不调用外部 API。不重训检测器、验证器。
- 预计 SECOND test 加 second_cv 全部影像在 CPU 上 1 小时内完成；超过 3 小时先停下报告。

## 第 1 步：逐块估计局部偏移
对 SECOND test 和 second_cv 的每对影像（512×512）：
1. 两期转灰度，各自减均值、除标准差。
2. 在 64×64 窗口、步长 32 的网格上，用相位相关（`skimage.registration.phase_cross_correlation`，`upsample_factor=4`，`normalization=None` 或 `"phase"`，二者先在第 2 步的合成数据上比较，选误差小的）估计 t2 相对 t1 的平移 (dx, dy)。
3. 每块记录：偏移量、相关峰值与次峰值之比（或 `error` 返回值）、块内纹理强度（灰度标准差）、块内真值变化像素占比。
4. 有效块：真值变化占比 < 10%、纹理强度高于全体块的 20 分位、峰值比高于阈值（阈值在合成数据上定，使合成偏移的误差 ≤ 1 像素的比例 ≥ 90%）。无效块的偏移用邻近有效块插值，并标记为插值值；整张图有效块 < 4 个时，该图标记为“无法估计”。
5. 另外对每张图在“全部有效块”上取中位数，作为**整图偏移**；局部偏移减去整图偏移，作为**残余局部偏移**。

### 第 2 步：校验估计方法（必须先做）
- 合成校验：随机取 50 张 test 影像的 t1，人为平移 (dx, dy) ∈ {0, 2, 5, 10} 像素（含非整数如 2.5），与原 t1 配对估计，报告各窗口大小（32、64、96）下的平均绝对误差和失败率，选定窗口大小与阈值。
- 真实校验：对 `test_857.png` 切块 18 所在位置的估计偏移，应在 8–12 像素左右（6g 中目测约 10 像素）；若偏差很大，先排查方法再继续。
- 另外人工挑 5 个估计偏移最大的块，保存两期裁块并排图到 `figures/exp6i/check/`，确认是真错位而不是真变化或纹理重复造成的误匹配。

## 第 3 步：把偏移挂到切块上
- 对 6a 切块池（`pool/<dataset>/pieces.jsonl` 与对应掩膜）中每个切块，取掩膜覆盖的各网格块偏移的面积加权平均，得到切块偏移 |d|（像素）、它是否来自插值，以及**相对偏移** |d| / 切块外接框长边。
- 偏移分桶：< 1、1–3、3–6、> 6 像素；相对偏移分桶：< 0.1、0.1–0.3、0.3–1、> 1。
- 同时给 6g 的 320 个审核样本（按 `image` + `piece_id` 关联）附上偏移，存 `audit/samples_offset.json`（新文件，不改 `samples.json`）。

## 第 4 步：统计
1. **偏移分布**：整图偏移、残余局部偏移的分布（直方图 + 分位数）；整图偏移 > 2 像素的影像占比；残余局部偏移 > 3 像素的块占比。回答偏移是全局为主还是局部为主。
2. **切块层面**：各偏移桶内的切块数和占比，按以下维度交叉：真值标签（正/负）、来源（B、G0.05、C1、C2、H1、pred）、是否由 SLIC 切分（`split`）、面积桶（< 50、50–300、300–1000、> 1000）。重点看 C1 和小切块。
3. **对 V1 的影响**：用 6b none 版本的分数，按偏移桶（和相对偏移桶）分别报告 AUC、AP，以及阈值 0.820 下负例的误检率。看 S3 定义的“高分负例”中大偏移切块的占比，与全体负例对比。
4. **对 6g 审核的影响**：报告 320 个审核样本的偏移分布、各分层大偏移样本占比。如果 `audit/` 下已有人工结果（`audit_answers.json`），再报告各偏移桶内人工与真值的不一致率；没有就跳过并写明。
5. 偏移最大的 10 个负例切块，存并排图（近景加轮廓，同 V2 裁法），每张一句说明。

## 判断问题（写进结果文件）
1. SECOND 的两期偏移有多大？以全局还是局部为主？test 与 second_cv 是否相近？
2. 多少比例的负例切块受明显偏移（> 3 像素，或相对偏移 > 0.3）影响？是否集中在 C1、小切块、高分负例？
3. V1 在大偏移切块上是否明显更差？差多少？
4. 据此，下一步应该：（a）不处理；（b）在流水线前加整图配准；（c）V1/V2 改为容忍局部偏移（例如 t2 特征在 ±k 像素邻域内取与 t1 最相似的位置再池化，或 V2 的近景框放大）；（d）候选或评估中排除“小切块 + 大相对偏移”的样本。给出建议和理由，并估计各方案的工作量。
