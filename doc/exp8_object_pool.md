# 任务：实验 8，四个数据集上以对象为单位重建候选池

给服务器上的 Claude。前置结果见 `results/summary.md`、`results/exp2_oracle.md`、`results/exp5c_end_to_end.md`、`results/exp6e_fp_removal.md`、`results/exp6i_misregistration.md`、`figures/exp6g/all_pieces/test_759/README.md`、`doc/exp6g_label_noise.md`（6g 审核）、`doc/exp7_prompt_refinement.md`（7b 判断单元对比）、`doc/eval_metrics.md`。

本实验分两部分：**A 部分**只做候选池和数据质量统计，不训练；**B 部分**在新池上重训 V1 无骨干版（只用元数据特征，代价小）。不调用外部 API，不训练检测器。

## 为什么做

### 1. SECOND 的数据问题（数据集照常使用，解读结果时要考虑）
- **标注口径有争议。** 6g 人工审核（Ethan，300 个独立切块，另 20 个重复项；审核者非专家，答案只作参考）中，S5 分层里可判断的“植被 → 植被”正例（均为 tree ↔ low vegetation）有 9/16 被判为没变，目测多为季节性植被（落叶 / 茂盛、绿 / 黄；原因未单独记录）。test_518 中一栋看起来只换了屋顶颜色的建筑被标为“建筑 → 建筑”的变化，而相邻同样换色的厂房没有标（`figures/exp6g/gt_clean/test_518.png`）；两期影像不能排除翻修重建，属疑似口径不一致，待复核。是否把这类外观变化算作变化，正在请导师确认。
- **审核一致性有限。** Ethan 对 20 个重复项的自一致为 16/20（80%，含“跳过”一致）。原稿中“两名审核者（Ethan、Claude）一致率 69–85%”在仓库中没有逐项记录，无法复核，已删去；审核者间一致率待补第二审核者的原始答案。人难以判断的正负例，模型也难学好。
- **难漏检正好集中在争议类别上。** 摸底实验中无信号漏检像素占比：改建（建筑 → 建筑）40%，植被相关 25–43%，地表 ↔ 植被 21–26%，新建建筑只有 1.8–5.4%。SECOND 补漏上界 +7.81 中有多少来自这些争议类别，目前没有统计（见第 6 步）。
- **分辨率与配准。** SECOND 影像分辨率较低，部分小切块人眼也难判断；6i 显示可估计偏移的负例中约 57% 偏移超过 3 像素（测试负例约 84% 无法估计；与 V1 失败关系弱，暂不处理）。分辨率是否是主要原因尚未证实，不作为结论。
- **SECOND 没有替代品。** 它是多类语义变化里最常用、也最难的数据集，必须继续使用（2026-10-21 与师兄讨论确定）。所以对 SECOND 的做法是：照常训练和评估，主结果按原始真值报告，同时用第 6 步把争议类别的影响单独量化。

### 2. 现有候选池质量低、数量过大
- test_759 一张图有 **1,302 个切块**，却只来自 **221 个原始候选**：86% 的切块（1,122 个）是 SLIC 把大候选按约 298 像素的目标尺度切开得到的（实际切块面积中位 164、P90 289）；221 是按来源与候选号回并的数，含 pred；六个来源（B、G0.05、C1、C2、H1、pred）互相重叠，没有跨来源去重。
- 正 330、负 883、中间 89。该图中几乎每栋没变的厂房都被切成一堆负例方块；训练池整体是否也以“没变的建筑碎块”为主，尚未统计（第 2 步补）。
- 这样的单元数无法接 MLLM 逐个判断或修改：V2 全池推理需 330 GPU 小时以上（6b）。

### 3. 四个数据集的定位
| | LEVIR | WHU | SYSU | SECOND |
|---|---:|---:|---:|---:|
| 检测器 F1 | 92.88 | 93.20 | 84.58 | 74.17 |
| 2b 补漏上界（真值框提示 SAM3） | +0.50 | +1.18 | +1.89 | +7.81 |
| 2a_select 精修上界（完美判断） | +0.50 | +0.79 | +1.62 | +1.50 |
| 两侧都做对 | +1.00 | +1.95 | +3.48 | +9.05 |
| 6e 切块级去误检上界 | – | – | +4.07 | +5.74 |

- 数据集暂定为 LEVIR-CD、WHU-CD、SECOND、SYSU-CD 四个，先在四个上都跑出 baseline。
- LEVIR / WHU 检测器已有 F1 93，补漏和精修的像素 F1 空间都在 1–2 个点内，主要用来证明方法“不伤好结果”，以及在边界指标上体现精修。
- SYSU 是通用变化（建筑、道路、植被、填海等），空间中等，标注问题是否比 SECOND 少尚无直接证据（人工审核只覆盖 SECOND），可作为“问题出在数据还是方法”的对照。在完美确认（oracle）条件下，4c 在 SYSU 上拿到 2b 上界的约 96%（+1.81 / +1.89），SECOND 只有约 19%（+1.46 / +7.81）；两者覆盖范围不完全相同（2b 只补整目标漏检），比值只作粗略参考；不靠真值的最好结果 SYSU −0.19，SECOND −0.73。
- SYSU 上候选级（不切细）oracle 已有 +2.21，切块级 +2.96（5c）；SECOND 是 +3.05 对 +6.96。SYSU 候选级比切块级少 0.75 个百分点（约损失切块级增益的 25%），损失比 SECOND 小，但是否可接受待验证；原始候选也不等同于去重取并集后的对象。
- SYSU 的去误检上界（+4.07）高于补漏一侧（+2.96），所以“漏检识别”和“误检定位”两件事都值得在 SYSU 上做。
- **SYSU 只有二值变化标签，没有 t1 / t2 语义标签。** 这不影响本实验：候选来源 B 用的是 SAM3 预测的类别，不是真值语义；训练标签只用二值图的真值占比。代价是：没有来源 A（检测器语义头，SChanger 本来就没有）、不能按（t1 类别，t2 类别）拆分变化类型。（更正：原稿称 6h 依赖语义标签，不对；6h 的两种做法都只用二值变化真值。）需要变化类型时，只能用 SAM3 预测的类别近似，并写明是预测值。

### 4. 分工
两条优化方向并行：（1）漏检找回；（2）MLLM 借助提示调用 SAM3 等工具优化掩码，向精修上界和补漏上界靠拢（精修方法见 exp7）。本实验负责两条线共同的上游：候选聚合和数据质量。
- **SECOND**、**SYSU-CD**：补漏（漏检找回）和去误检都做，候选聚合在两者上都要测。
- **LEVIR-CD、WHU-CD**：做误检定位和掩码精修。LEVIR 的误差像素有 74% 是边界误差，像素 F1 难体现，用 `doc/eval_metrics.md` 的 Boundary F1、Boundary IoU、边界粗糙度报告；精修方法沿用 exp7（exp7 已含 LEVIR / WHU 的 O 设定）。
- 候选聚合（第 1 步）在四个数据集上都做。

## 规则
- 不修改任何官方影像和真值。不训练检测器。
- 参数只在验证部分选，测试集每个冻结方案只评一次。
- 每一步先报告数字再进入下一步；第 0 步发现训练数据不可用时，停下来报告。
- 新代码放 `code/probe/exp8_*.py`，可复用 6a / 6b 的代码，但不要改动它们的默认行为（旧结果要能复现）。

## 与 exp7 的执行顺序
服务器队列是 `eval_metrics` → exp7 → 流程页更新，exp8 排在它们之后。其中**第 0 步和第 6 步不依赖 exp7，可以先做**（第 6 步最便宜，且决定 SECOND 结果怎么解读，放在最前）。第 1 步的 U4 和第 4 步的对象级单元复用 7b 的 SAM 对象级划分，等 7b 出结果后再做；其余部分按步骤顺序进行。

## 第 0 步：盘点数据（必须先做）
1. 服务器上 SYSU-CD、LEVIR-CD、WHU-CD 各自有哪些划分（train / val / test）、张数、尺寸；`results/env.md` 目前只登记了 SYSU 的 test。查阅数据集论文或说明，写明三者的地面分辨率（SYSU 应为 0.5 米航拍，请核实）。
2. 训练池来源。SECOND 用的是交叉拟合检测器（`second_cv`），SYSU 没有。按以下顺序选第一个可行的，并写明理由：
   - (a) SYSU 官方 val 划分 + 官方 SChanger-small 权重的预测（检测器没在 val 上训练，预测分布接近 test；注意官方可能用 val 选过权重，写明这一点）；
   - (b) SYSU train 划分 + 官方权重（检测器在 train 上过拟合，漏检和误检会偏少，只作为后备）；
   - (c) 都不可行就停下报告，不要自行重训检测器。
   LEVIR / WHU 同理，先写明可用划分，B 部分再用。
3. 训练池内按图像划分训练 / 验证（例如 80 / 20），同一张图不跨划分。

## A 部分：候选池与数据质量（不训练）

### 第 1 步：对象级候选池（四个数据集都做）
候选来源沿用 5c：SYSU 用 B + G0.05（5c 中 H1 在 SYSU 上不比 B 好）；SECOND 用 B + G0.05 + H1；LEVIR / WHU 用 B + G0.05（如果这两个数据集还没有候选，按 5c 的做法先生成，B 只保留 building 类）。不加 C1、C2、pred（pred 属于去误检一侧，见第 4 步）。
1. **跨来源去重**：同一张图内，两个候选掩码 IoU ≥ 0.5，或较小者有 ≥ 80% 面积落在较大者内，就合并为一个对象（取并集），记录它来自哪些来源（多来源一致本身可作为特征）。写明合并的传递规则。
2. **不切 SLIC。** 判断单元就是去重后的对象。另做三个对照：U0（现有 SLIC 切块）；U4（SAM 对象级划分，与 7b 同一做法；若 7b 已产出，直接复用其单元，不重复实现）；**U5 混合**：去重后面积超过阈值的大对象用 U4 的划分再拆开，其余对象保持完整（阈值在验证部分选，候选为无信号漏检目标中位面积的 4、8、16 倍）。
   - 注意：SECOND 上候选级（不切细）oracle 只有 +3.05，切块级 +6.96（5c），去重取并集还会让大对象更大、更不纯。U5 用来检验能否在单元数大降的同时保住大部分上界。
3. 每种单元报告：每图单元数（均值、P50、P90）、面积分布、标签分布（真值占比 ≥ 50% 为正、< 10% 为负、其余为中间）、**中间样本占比**（标签纯度）、无信号漏检的目标覆盖率和像素覆盖率、oracle ΔF1（单元内真值占比 ≥ 50% 才并入）。
4. test_759 上同时报告旧池（1,302 切块 / 221 候选）与新池的单元数，画一张与 `figures/exp6g/all_pieces/test_759/before_split.png` 同样式的新池图。

### 第 2 步：数据质量表与规则清洗
1. 对新池（SECOND、SYSU 的训练部分）统计以下几类“低质量单元”的数量、占比、标签分布和 oracle 贡献：
   - 极小单元（面积 < 50、< 100 像素）；
   - 细条（外接框短边 ≤ 3 像素，或面积 / 外接框面积 < 0.2）；
   - 碎片（同一对象被多个来源部分覆盖后残留的、与其他单元重叠 > 50% 的单元）；
   - 中间标签单元（真值占比 10–50%）。
2. 给出一套清洗规则（只用于训练集，测试集不清洗），报告清洗后训练集的规模和正例率，以及清洗掉的单元在 oracle 下损失多少 ΔF1。
3. **四个数据集各生成一份新审核页**，每份 200 个对象，从第 1 步的对象级新池（测试集）抽取，按“正 / 负 / 高分负例 / 中间标签”分层，分层比例写进页面说明；另加 10% 重复样本检查自洽。用 6g 的审核网页工具（`code/probe/exp6g_page.py`、`exp6g_sample.py`），输出到 `audit/exp8_<数据集>/`。页面里显示的是对象轮廓，而不是 SLIC 切块；近景和上下文两种视图保留。只生成页面，人工审核由 Ethan 来做。

## B 部分：在新池上重训和评估

### 第 3 步：补漏（SECOND、SYSU）
1. SECOND 用现有交叉拟合训练池（`second_cv`），SYSU 用第 0 步选定的训练池。在对象级新池上重训 V1 无骨干版（与 6b none 相同的元数据特征，加上“来源个数”“来源组合”）。另训一份用清洗后训练集的版本。
2. 对照：检测器概率规则（5c 最好的切块级设定）、旧 U0 池上的 V1 none（SECOND 已有 6b 结果；**SYSU 必须按 6b 流程在同一训练池上训一份**，否则无法区分新池的收益来自对象单元还是 SYSU 本身更容易）。
3. 报告 AUC、AP、召回 80% 时的误检率和像素精度（与 F1/2 比较，SECOND 约 37%，SYSU 约 42%）、端到端 ΔF1（阈值在验证部分选）。
4. **级联统计**：在验证部分定两个阈值，高于上阈值直接接受、低于下阈值直接丢弃，中间为“不确定”。报告上下阈值取不同值时，每图不确定对象数、它们的正例率、以及“只并入接受部分”的 ΔF1。这是后续是否接 MLLM 的依据，本实验不调用 MLLM。

### 第 4 步：去误检（四个数据集）
1. 把检测器 0.5 掩码按连通域拆成预测区域。单元两种：(a) 6e 的 SLIC 切块；(b) 预测区域与 SAM 对象级划分求交得到的对象级单元（与第 1 步的 U4 同一做法）。
2. 每种单元报告 oracle 去误检上界（与 6e 同口径）、每图单元数，以及 `doc/eval_metrics.md` 的边界指标。
3. 在对象级单元上训练去误检判别器（同样的元数据特征 + 检测器在单元内的平均概率），对照“以检测器在单元内的平均概率打分”（SECOND pred 切块上 AUC 0.784，见 `results/exp6b_verifier.md`），并在每个数据集、每种单元上重算。报告 ΔF1 和边界指标。LEVIR / WHU 要求 ΔF1 ≥ −0.3（不伤好结果）。
4. 精修只对接 exp7，不在本实验内实现新的精修方法。

### 第 5 步：baseline 汇总
- 把四个数据集的检测器原始结果、第 3、4 步的结果放进同一张表，指标按 `doc/eval_metrics.md`（像素 F1、IoU、Boundary F1、Boundary IoU、边界粗糙度、目标 F1）。如果 `eval_metrics.md` 的基础表已经跑过，直接引用，不重跑。

### 第 6 步：SECOND 补漏上界按变化类型拆分
- **本步不依赖其他步骤，先于第 1 步做。** 实验 2 的 2b 上界（+7.81）和 5c 切块级 oracle（+6.96）按真值的（t1 类别，t2 类别）拆开，分成：新建建筑、拆除、改建（建筑 → 建筑）、植被 ↔ 植被、地表 ↔ 植被、水体相关、其他。报告每类贡献的 ΔF1 和像素占比，回答“上界有多少来自有争议的类别”。

## 判断问题（写进结果文件）
1. 跨来源去重、以对象为单位后，四个数据集每图单元数各降到多少？oracle ΔF1 损失多少？
2. 新池的标签纯度（中间样本占比）、正例率与旧池相比如何？清洗规则去掉了多少训练样本，代价多大？
3. 在 SECOND、SYSU 上，对象级新池重训的 V1 能否让端到端补漏 ΔF1 转正？与检测器概率规则相比如何？
4. 级联中不确定区间每图有多少对象？如果只把这些对象交给 MLLM，按 V2 的单次耗时估算全测试集需要多少 GPU 小时？
5. 去误检在四个数据集上能否带来正的 ΔF1 或明显的边界指标改善？LEVIR / WHU 是否满足 ≥ −0.3？
6. SECOND 上 +7.81 的上界中，改建、植被相关等争议类别占多少？
7. 据此建议：候选聚合是否作为两条优化线的统一上游？SECOND 与 SYSU 的结论是否一致，不一致时更像数据问题还是方法问题？还缺什么？
