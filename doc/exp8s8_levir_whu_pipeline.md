## 背景（Ethan 2026-10-27）
- 补漏流程只在 SECOND、SYSU 上完整走过。LEVIR、WHU 以建筑变化为主，更简单，但 exp8 只给它们建了**测试**候选池，没有训练 / 验证池，判断器也没训过。
- 这两个数据集要补上，一是检查流程本身在简单数据上是否成立，二是给后续 MLLM 上下文示例（`doc/exp6k_icl_demo_prep.md`）提供训练 / 验证候选。
- 预期要放低：LEVIR 的漏检里 ①+② 只占约 16%，exp2 的补漏上限约 +0.5 F1。本实验主要回答“流程是否走得通、各环节数字是否合理”。

## 规则
- 允许运行检测器、SAM3 等生成候选，但**先估算 GPU 小时**：总计预计超过 24 GPU 小时时先停下报告。
- 选择只用验证部分，测试部分只评一次冻结方案。
- 不调用外部 API。

## 第 0 步：划分与检测器
- LEVIR：官方 train 445 / val 64 / test 128（原图）。WHU：官方 train 1,260 / test 690，**没有 val**：从 train 按图（或按空间块，避免相邻切块泄漏）划出验证部分，写明做法。
- **训练部分的检测器预测不能直接用官方权重**：官方检测器在训练图上过拟合，漏检会太少、分布与测试不同。参照 SECOND 的 `second_cv`，做交叉拟合（训练部分分 K 折，每折用其余折训练检测器并预测该折）。K 与训练轮数由你定，优先复用已有的交叉拟合产物；GPU 小时先估算。若成本过高，提出替代方案（例如只交叉拟合一部分训练图），先报告。
- 验证、测试部分用官方权重（与 exp8 测试池一致）。

## 第 1 步：候选池
- 来源与单元沿用 exp8 测试池的冻结设置：来源 B+G0.05（B 只保留建筑有无差异）；LEVIR 用 U5_x16，WHU 用直接对合并对象（若你认为 WHU 也该用 U5，写明理由，并在测试池上同时报告两种）。
- 在训练、验证部分生成候选池，口径与测试池完全一致。

## 第 2 步：四类漏检与分流
- 按 exp8s2 的定义统计训练 / 验证 / 测试各部分的 ①②③⑤ 像素与对象占比，另报距离 > 5 像素的 ②。
- 用 1d 冻结规则（单元自身 r < 0.1）分流，报告补漏组 / 精修组单元数、① + ② 被补漏组覆盖的比例、③ 误分到补漏组的比例（同 exp8s2 第 1d 步口径）。

## 第 3 步：碎片过滤
- 同 exp8s6：比较去细条 + 新增面积 ≥ A（A = 0、100、200、300、500）以及开运算 + ≥ 100。
- 选择规则：验证部分 ② 对象覆盖相对不过滤的损失 ≤ 10 个百分点时，每图单元最少；LEVIR、WHU 分开选，冻结后在测试部分报告。训练部分同样过滤。

## 第 4 步：判断器
- D（单元内检测器均值，不训练）；M1（元数据两层 MLP，结构同 exp8s3，只用过滤后的补漏组训练）；M1-ign3；oracle。
- 主指标：“② 正例 vs 补漏负例”的 AUC / AP（按图整群自助法 95% CI）；预算曲线（每图前 k 个，k = 1、2、3、5、10、20、全部，② 对象召回上限，口径同 exp8s5）。
- 冻结点：验证选 ΔF1 = −0.3、−0.5、−1 的阈值，测试报告 ΔF1、② 对象召回、新增误检连通域 / 图。

## 第 5 步：导出候选清单
按 `doc/exp6k_icl_demo_prep.md` 的格式，导出 LEVIR、WHU 的训练、验证、测试候选清单，供第 6 步使用。
