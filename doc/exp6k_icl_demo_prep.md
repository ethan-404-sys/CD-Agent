# 任务：实验 6k（准备），MLLM 上下文示例（ICL）的示例与样本准备

给服务器上的 Claude。前置：`results/exp6j_rs_mllm_zero_shot.md`（零样本结果与判错分析）、`results/exp8s6_filter_coverage.md`（冻结的碎片过滤）、`results/exp8s3_stage1_judge.md`（补漏组标签）。参考论文：Jiang 等 *Many-Shot In-Context Learning in Multimodal Foundation Models*（arXiv 2405.09798）。

**本文件只做准备：挑示例、写数据集变化口径、构建开发集与测试样本、渲染示例。不跑任何 MLLM 评测**，评测另写文档。

## 背景（Ethan 2026-10-27）
- exp6j：零样本 MLLM 在补漏组上接近随机，判错全是“无变化判成有变化”（季节色调、屋顶换色等）。原因之一是模型不知道每个数据集“什么算变化”。
- 下一步要比较的提示方式（评测阶段做）：
  - 零样本，但系统提示按数据集的变化特点改写（写清什么算变化、哪些伪变化不算）；
  - 少示例 ICL；
  - 多示例 ICL；
  - 批量提问（一次请求放多个待判候选，参考 Jiang 等）。
- 示例形式（评测阶段做消融）：
  - **A**：与任务对齐，T1 近景、T2 近景（红色轮廓画候选新增像素）、答案和一句理由；
  - **B**：整图 T1、T2、变化掩码（二值）；SECOND 另加两期语义信息；
  - **A+B**：两者都给。
  - 小模型只用 A；闭源大模型 qwen3-vl-plus 用 A / B / A+B。
- **伪变化本质就是无变化**：不单设类别，答案一律是“无变化”，只在理由里写明属于哪种伪变化（例如“屋顶换色，属于无变化”）。
- 数据集：本轮只做 **SYSU、SECOND**（候选池现成）。LEVIR、WHU 等 `doc/exp8s8_levir_whu_pipeline.md` 建好训练 / 验证候选池后再加。

## 规则
- 示例**只从训练部分**挑；开发集从**验证部分**抽；测试样本从**测试部分**抽。三者互不重叠（按图划分）。
- 所有候选都是 exp8 的 U5_x4 单元，1d 冻结规则分到补漏组，再套 exp8s6 冻结的过滤（SECOND：去细条 + 新增 ≥ 200 像素；SYSU：开运算 + 新增 ≥ 100 像素）。判断对象是新增像素。
- 标签同 exp8s3：新增像素真值占比 ≥ 50% 为“有变化”，< 10% 为“无变化”，中间不用。
- 不跑 MLLM、不训练。挑示例和打理由时如需看图，由你（Claude）看渲染好的图判断。

## 第 1 部分：数据集变化口径（写进系统提示的材料）
每个数据集写一页：
- 这个数据集标注的“变化”指什么（SYSU：二值，覆盖哪些地物变化；SECOND：6 类地物之间的语义变化，二值变化 = 两期类别不同）；
- 哪些情况**不算变化**（伪变化），每种给一句判断要点：季节 / 物候、光照与阴影、色调 / 成像差异、同一地物外观变化（如屋顶换色、材质翻新）、车辆等临时物体、配准错位，以及你从数据中发现的其他类型；
- 依据：官方论文或数据集说明里的定义（请 Codex 从知识库查找并给出处）+ 你在训练数据难负例上看到的情况。
- 给出一版可直接用的系统提示草稿（中英文各一版），并写明哪些说法有出处、哪些是从数据里归纳的。

## 第 2 部分：示例池
每个数据集从训练部分挑一个示例池，供评测阶段按数目和选法抽取：
- **规模**：约 64 个示例（正、负各约一半），足够做少示例和多示例（多示例若要更多，按同样规则扩展到 256 个，另存一份）。
- **代表性要求**：
  - 正例覆盖不同面积档、不同来源；SECOND 按变化种类（t1 类别 → t2 类别）尽量平衡，写明各种类的数量；
  - 正例以 ② 为主，同时包含一部分 ①；
  - 负例中至少一半是**难负例**（检测器均值高、或外观差异明显但真值无变化），并按伪变化类型尽量覆盖第 1 部分列出的各类；其余为普通负例；
  - 避开真值可疑和太小看不清的单元；
  - 同一张图最多取 2 个示例。
- **每个示例记录**：图名、单元 id、标签、一句理由（正例写变化内容，例如“裸土 → 建筑”；负例写伪变化类型，例如“屋顶换色，属于无变化”）、面积、来源、检测器均值、SECOND 的 (t1, t2) 类别。
- **渲染**：每个示例同时渲染 A 形式（384 像素近景，红色轮廓）和 B 形式（整图 T1、T2、二值变化掩码；SECOND 另附两期语义类别的文字说明，必要时附语义图），存成文件，评测时直接调用。

## 第 3 部分：开发集与测试样本
- **开发集**：从验证部分抽，每个数据集约 600 个候选，分层（② 为主的正例、其他正例、难负例、随机负例），记录抽样权重。评测阶段所有选择（示例数、选法、示例形式、提示写法）都在开发集上做。
- **测试样本**：从测试部分抽，每个数据集约 1,500 个候选，同样分层并记录权重，用于最终报告。所有模型、所有方案用同一批。
- 每个样本同时存 A 形式输入，并按图分组（批量提问要用同一张图的全部候选），记下每张图的候选清单。

## 第 4 部分：示例审核页
用 Artifact 工具发布一个简单页面，让 Ethan 审核示例池：
- SYSU、SECOND 分两个标签页；正例、负例分组，负例按伪变化类型分小组，SECOND 正例按变化种类分小组；
- 每个示例一张卡片：T1、T2 近景（红色轮廓）、整图缩略图（画出候选位置），下方写标签、理由和关键数值；
- 顶部写明示例池的构成统计（各类数量），以及第 1 部分的系统提示草稿。
