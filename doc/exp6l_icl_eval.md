# 任务：实验 6l，基于提示的 MLLM 补漏判断评测（数据集口径提示 + 上下文示例）

给服务器上的 Claude。前置：`results/exp6j_rs_mllm_zero_shot.md`（零样本基线与判错分析）、`results/exp6k_icl_prep.md`（示例池、开发集、测试样本、系统提示 v1）、`audit/verifier_ui/README.md`（写库接口，用 PR #1 最新提交）。参考论文：Jiang 等 *Many-Shot In-Context Learning in Multimodal Foundation Models*（arXiv 2405.09798）。

## 为什么做
- exp6j：零样本 MLLM 在补漏组上接近随机，判错全是“无变化判成有变化”，因为模型不知道每个数据集“什么算变化”。
- exp6k 已准备好数据集口径提示和示例池，Ethan 已在前端审核完示例池（2026-10-27）。
- 本实验回答：**把数据集口径写进提示、再给示例，MLLM 能否在补漏组上把 ② 和无变化分开，并超过检测器均值 D 和 M1-ign3。**
- 数据集：本轮 **SYSU、SECOND**。LEVIR、WHU 的材料由 exp8s8 第 6 步准备，审核完后按同一设计补跑。

## 规则
- **示例**只用审核后的示例池：`export_demos.py` 导出，去掉 Ethan 剔除的。若某一层（② 正例 / 其他正例 / 难负例 / 随机负例）被剔除超过 25%，从同一层的训练候选按同样规则补齐，写明补了哪些。
- **所有选择**（示例数 k、选法、示例形式、提示写法、ICL 形式）只在**开发集**上做；**测试样本**只对每个模型的冻结方案评一次。
- **防泄漏**：语义文字（`semantic_text`）用了真值，只能出现在示例里，查询样本一律不给。B 形式的文字统一用 `store.semantic_line(t1, t2, semantic_full)`。
- **全部运行写进审核前端库**：用 `RunRecorder`（`form=`、`pool=`、`eval_set=`、`readout=`；批量提问用 `record_batch(..., group_key=image)`，`batch_by='image'`；闭源模型的调用带 `usage`）。
- **资源**：服务器 GPU 紧张，本地小模型的作业等 exp8s7 结束后再排；先估算 GPU 小时，阶段一超过 8 GPU 小时先报告。qwen3-vl-plus 走百炼接口（Ethan 允许调用），**先估算调用次数、token 数和费用，报给 Ethan 确认后再跑**；它不占 GPU，可以先跑。
- 提示词用英文版（`*_sys_v1_en`）；中文版只供 Ethan 阅读。

## 模型
- 本地小模型：Qwen3.5-4B（exp6j 在补漏组上最好的）和 Mini-InternVL2-4B-DA-RS。EarthDial 只在阶段二作对照（exp6j 中它在 SYSU / SECOND 接近随机）。
- 闭源大模型：qwen3-vl-plus（百炼）。
- 读数：小模型同 exp6j，取 yes / no 词元概率；qwen3-vl-plus 若接口给词元概率就用，否则让它输出 0–100 的置信度，`readout` 写明。

## 比较的提示方式
| 记号 | 说明 |
|---|---|
| Z0 | exp6j 原零样本提示（对照，可直接复用 exp6j 在同样本上的结果，样本不同则重跑） |
| Z1 | 零样本 + 数据集口径系统提示（`*_sys_v1_en`） |
| F | 少示例 ICL：Z1 + k 个示例，每次请求问一个候选 |
| M | 多示例 ICL：同 F，k 更大 |
| BQ | 批量提问：Z1 + k 个示例，一次请求问同一张图的全部候选（参考 Jiang 等的批量做法） |

- 示例按“用户提问 + 助手回答”的多轮对话放在系统提示之后，最后才是查询。
- 示例形式：小模型只用 A（T1、T2 近景 + 答案 + 一句理由）；qwen3-vl-plus 比较 A、B、A+B。
- 示例数 k：所有模型统一只用 0、4、8、16（Ethan 2026-10-27 定）。放不下就到能放下为止，写明上下文长度。不再跑 32 以上的多示例档位。
- 选法：类别平衡的随机抽取（3 个种子）vs 按相似度检索（相似度怎么算由你定，例如用冻结的遥感骨干特征；写明理由）。

## 阶段一：开发集（每个数据集 600 个）
1. 每个模型先跑 Z0、Z1。
2. 每个模型跑 F：A 形式，k 网格 × 两种选法。
3. qwen3-vl-plus 在最好的 k 上比较 A / B / A+B（不再单独跑 M 的大档位）。
4. 在最好的设置上跑 BQ，比较与逐个提问的差别和成本。
5. 每个模型按开发集上“② 正例 vs 补漏负例”的 AP 冻结一个方案（同分时取更便宜的）。

## 阶段二：测试样本（每个数据集 1,500 个）
- 每个模型的冻结方案各评一次；同时报告同样本上的 D、M1-ign3，以及 exp8s7 最好判断器的分数（若已完成）。
- EarthDial 用 Qwen3.5-4B 的冻结方案评一次作对照。

## 指标
- 主指标：“② 正例 vs 补漏负例”的 AUC、AP，按抽样权重还原（2000 次按图整群自助法 95% CI）。
- 分层（四栏）：② 正例、其他正例、难负例、随机负例上的答“是”比例；难负例那一栏要单独讨论，看口径提示和伪变化示例有没有压住“无变化判成有变化”。
- 示例数曲线：横轴 k，纵轴开发集 AP，每条线一个模型 × 选法（前端“示例数量曲线”视图）。
- 成本：每个候选的平均耗时（小模型）或 token 数和费用（qwen3-vl-plus）；换算成“测试集全量、每图前 k 个候选”的总成本（候选数见 `results/exp8s6_filter_coverage.md`）。

## 错误分析
从测试样本每个数据集各抽 10 个“最好方案判错、D 判对”和 10 个“最好方案判对、D 判错”，归为：认错地物 / 季节或色调 / 屋顶换色等同一地物外观变化 / 配准错位 / 真值可疑 / 太小看不清 / 其他。

## 判断问题
1. 只加数据集口径（Z1）比 Z0 好多少？难负例上答“是”的比例降了多少？
2. 加示例后，AP 随 k 怎么变？随机选和相似度检索哪个好？
3. qwen3-vl-plus 比小模型好多少？A / B / A+B 哪个好？批量提问是否掉点？
4. 最好的方案在测试样本上能否明显超过 D 和 M1-ign3（例如 ② AP 高 0.05 以上）？
5. 按最好的方案，测试集全量判断一遍要多少 GPU 小时或多少费用？
