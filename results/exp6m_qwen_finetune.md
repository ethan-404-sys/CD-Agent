# 实验 6m：分数据集 LoRA 微调 Qwen3.5-4B 做补漏判断（2026-10-29）

任务文档：`doc/exp6m_qwen_finetune.md`。代码：`code/probe/exp6m_*.py`。训练曲线：`figures/exp6m/`。

**结论**：两条过关线在 SYSU 和 SECOND 上都没过。微调让 Qwen3.5-4B 比只用提示和示例（exp6l k=16）更好：② AUC 在 SYSU 从 0.726 升到 0.802，在 SECOND 从 0.572 升到 0.638。但它单独用时明显低于 exp8s7 的融合分数，与融合分数做晚融合也没有增益。按文档规定，MLLM 在补漏判断上到此为止。

## 2. GPU 估算与实际用量

Qwen3.5 的线性注意力层在现有环境里没有 flash-linear-attention 和 causal_conv1d，只能退回到 PyTorch 参考实现，所以训练慢。以 200 步计时实验为依据，比较了几种配置：

| 配置 | 秒/步 | 显存峰值 |
|---|---:|---:|
| batch 1、累积 32、梯度检查点 | 24.4–26.7 | 9.4 GB |
| batch 8、梯度检查点 | 13.5 | 13.3 GB |
| batch 8、无检查点 | 显存溢出（80 GB） | |
| **batch 2、累积 16、无检查点（采用）** | **11.8** | 29.6 GB |

- 完整网格（两个数据集 × 三个比例 × 3 轮）约需 37 GPU 小时，超过 24 小时的上限。
- 因此改为两段方案：
  - SYSU 三个比例都训练 3 轮，每 100 步评估一次。
  - SECOND 三个比例先各训练 1 轮，比较验证 ② AP。选中的比例从第 1 轮检查点接着训练 2 轮，每 250 步评估一次。学习率按完整 3 轮的余弦计划。
- 实际用量：训练约 18.9 GPU 小时，测试推理约 0.4 GPU 小时，再加计时实验，共约 20 GPU 小时。

## 3. 训练设置

- **LoRA**：只加在语言模型的 q / k / v / o / gate / up / down 线性层上，视觉编码器冻结。
  - r = 16，alpha = 32，dropout = 0.05。
  - 学习率 1e-4，余弦计划，预热 3%。
  - 有效 batch 32，bf16，种子 1 个。
- **输入**：
  - 系统提示：数据集口径提示（`*_sys_v1_en`）。
  - 用户消息：T1、T2 两张近景（红色轮廓，与 exp6k 的渲染规则相同）和固定问题。
- **损失**：只算回答的 yes / no 这一个词元。
- **增强**：T1 / T2 同步翻转和 90° 旋转；以 0.5 的概率交换 T1 / T2。不做颜色增强。
- **选择**：只看验证集加权 ② AP，同分时取更早的检查点。

| 方案 | 训练 | 最佳验证 ② AP（步数） |
|---|---|---|
| SYSU 1:1 | 3 轮，198 步 | 0.065（198） |
| SYSU 1:3 | 3 轮，393 步 | 0.095（300） |
| **SYSU 1:5** | 3 轮，588 步 | **0.099（500）← 冻结** |
| **SECOND 1:1** | 1 轮后续训 2 轮，1,125 步 | **0.124（1,000）← 冻结**；第 1 轮结束时 0.116 |
| SECOND 1:3 | 1 轮，750 步 | 0.108（750） |
| SECOND 1:5 | 1 轮，1,125 步 | 0.110（1,125） |

**训练曲线**：每次优化步的训练 loss、学习率、梯度范数，和每次评估的验证 loss、② AUC / AP 都已记录。
- 图：`figures/exp6m/<run>.png`。
- 前端可读的数据：`figures/exp6m/curves/<run>.json`。
- SECOND 1:1 的训练 loss 从约 0.69 只降到约 0.6，模型在 SECOND 上学到的很有限。
- SYSU 1:5 的验证 ② AP 在第 100–500 步间稳步上升，之后回落。

### 过关线（预先注册）

| 数据集 | 1：微调 − 融合，区间下限 > −0.02 | 2：晚融合 − 融合 > 0.02，且区间不跨 0 | 结论 |

种子只用了 1 个。文档规定“结果接近过关线再补种子”，两个数据集都离过关线很远，所以没有补。

### 晚融合的实现缺陷

**问题**：融合分数不是概率，取值大约在 −4.6 到 3.1 之间。最初的实现把它截断到 [1e-6, 1−1e-6] 后再取 logit，两端大量样本因此变成并列值。
- SYSU 验证集：2,354 个值只剩 807 个不同值，网格中 w = 0 那一格的 AP 从 0.124 被压到 0.082。
- SECOND 验证集：3,544 个值只剩 1,702 个不同值，AP 从 0.204 被压到 0.161。

**发现时间**：SYSU 冻结并测试之后，SECOND 冻结之前。

**处理**：
- 改为微调概率取 logit，融合分数用原值，两者在验证集上分别 z 标准化。
- SECOND 是在修正之后冻结的。修正后 w = 0 的结果与融合分数完全一致。
- SYSU 维持原冻结方案和测试结果，没有重选，也没有重测。

**影响**：SYSU 的过关线 2 用的是有缺陷的融合。SECOND 用修正后的融合，测试结果也只是与融合分数持平（+0.000）。据此判断，修正不太可能让 SYSU 过关，但这一点没有实测。过关线 1 只用微调分数，不受影响。

## 6. 验证→测试落差

用同一套验证样本和测试样本计算。

| 方法 | SYSU 验证 | SYSU 测试 | SECOND 验证 | SECOND 测试 | SECOND 落差 |
|---|---:|---:|---:|---:|---:|
| 微调 | 0.099 | 0.111 | 0.124 | 0.087 | −0.037 |
| 晚融合 | 0.128 | 0.154 | 0.211 | 0.170 | −0.041 |
| 融合分数 | 0.124 | 0.157 | 0.204 | 0.169 | −0.035 |
| img-s1020 | 0.101 | 0.101 | 0.194 | 0.173 | −0.021 |
| D | 0.062 | 0.069 | 0.089 | 0.091 | +0.002 |

- SYSU 各划分用同一个官方检测器，没有落差，测试结果反而略高。
- SECOND 的训练集和验证集用交叉拟合检测器，测试集用官方检测器。微调分数在 SECOND 上的落差（−0.037）与融合分数（−0.035）相近。
  - exp8s7 在完整池上的落差是验证 0.206 → 测试 0.129，比这里大。那是完整池上的结果，这里是加权样本，两者口径不同。
- 结论：MLLM 只看图像，但并没有因此更不受检测器差异影响。原因是候选本身的构成也随检测器变化。
