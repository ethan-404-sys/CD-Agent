## 设定

**划分与检测器**（与 exp8 第 0 步一致）：
- SECOND：验证部分为 `second_cv` 的 297 张验证图，用交叉拟合检测器（F1 71.41）；测试 1694 张，官方 MambaSCD-Base（F1 74.16）。
- SYSU：验证部分为官方 val 中按原图分组留出的 800 张（pool_val），SChanger-small（F1 80.73）；测试 4000 张（F1 84.58）。
- LEVIR 测试 128 张原图（F1 92.88）、WHU 测试 690 张（F1 93.20），SChanger-Base，只做描述，不选任何东西。

**来源与旋钮**（全部在已缓存的输出上后过滤，没有重跑 SAM3）：

| 来源 | 定义 | 旋钮（档位） | 默认档 |
|---|---|---|---|
| G | 检测器概率 > t 的 8 连通域 | t = 0.05 / 0.1 / 0.2 / 0.3 / 0.4 | 0.05 |
| B | SAM3 两期类别做差（LEVIR/WHU 为建筑有无差异） | 原区域最小面积 0 / 50 / 100 / 200 / 500 | 0（不过滤） |
| H1 | AnyChange 全图模式 | 每图按分数取 top-K：全部 / 1 / 3 / 5 / 10 / 20 | 全部 |
| C | SAM3 建筑实例差（C1 未匹配实例 + C2 匹配对），内部先去重 | 原区域最小面积 0 / 50 / 100 / 200 / 500 | 0；C2 只保留分数 ≥ 验证部分 80% 分位数的候选（与实验 4a 的 C 相同） |

- B、C 选面积而不是置信度做旋钮：面积过滤不需要对 SAM3 置信度的刻度做额外假设。
- C2 切点只用验证部分计算：SECOND 0.4660，SYSU 用 pool_val，LEVIR 用官方 val 64 张；WHU 没有验证集，沿用 LEVIR 的切点（与 exp8 第 4 步 WHU 阈值的做法一致）。
- SYSU 验证部分原来没有 AnyChange 输出。经确认后补跑了 800 张（与实验 5 相同的设置，两片各约 19 分钟，合计约 0.6 GPU 小时）。

**候选与指标：**
- 每个候选只取检测器 0.5 掩码之外的部分（新增像素）；新增像素 < 20 的丢弃。默认档下丢弃比例：SECOND 测试 B 65%、H1 18%、G 31%、C 13%；SYSU 测试 B 75%、H1 38%。B 的原区域大多落在检测器掩码内，剩下的残片很小。
- 去重：exp8 第 1 步的 D1（IoU ≥ 0.5 或交集 / 小者面积 ≥ 0.8；按 IoU 降序配对，每个候选最多合并一次，取并集）。先在来源内部去重，再跨来源去重。
- 漏检对象：真值目标中检测器 0.5 掩码之外的 8 连通域，≥ 20 像素（实验 4 的最小面积；SECOND 先按语义转移拆目标）。“无信号漏检”：检测器覆盖 < 10% 的真值目标（实验 4 定义）。
- R_obj@τ：存在候选的新增像素与漏检对象 IoU ≥ τ 即命中。R_pix：候选新增像素并集覆盖全部漏检像素的比例（只作参考）。
- ΔF1_oracle（主指标）：只把新增像素精度 > F/2 的候选整块并入（F 为该划分检测器的 micro F1），按 micro 统计，单位为百分点。另报 exp8 口径（精度 ≥ 50% 才并入）。
- Frag：被命中（IoU ≥ 0.5）的漏检对象平均与几个候选重叠（重叠 ≥ 对象面积 10%）。Pos%：新增像素精度 > F/2 的候选占比。
- U5×4：exp8 第 1 步冻结的混合单元（B+G0.05+H1 的对象，大对象按 SAM 自动划分再拆），同样过滤新增像素 < 20，计数单位是单元。

**一致性核对：** 换回 exp8 第 1 步的候选条件后，在全测试集上复算 objects_direct_pairs 的 oracle：SECOND +4.692789…、SYSU +2.163875…，与 exp8 第 1 步逐位一致，逐图 TP/FP/FN 全部相同。

**“四源覆盖约 52%”的出处：** 实验 5a（`results/exp5a_anychange.md`）SECOND 测试集 B+C+G0.05+H1 的目标覆盖率 52.2%。口径是“无信号漏检目标中，被单个候选覆盖 ≥ 50% 且候选面积 ≤ 目标外接框 4 倍的比例”，用的是整个候选而不是新增像素。本实验同一并集在 SECOND 测试上的无信号漏检像素覆盖为 79.8%、无信号对象 R_obj@0.5 为 19.9%，口径不同，不能直接比。

## 第 1、2 步的初步回答

1. **四个来源的曲线形状（判断问题 1）。**
   - G 的阈值最敏感：从 0.05 提到 0.4，候选数几乎不变（SECOND 17.5 → 12.5），ΔF1 却从 5.21 降到 1.21。阈值只是把每个连通域缩小，不减少个数。G0.05 性价比最高：SYSU 验证部分每图 2.1 个候选就有 +3.64，是所有单来源中最高的。
   - B 的面积旋钮很划算：去掉原区域 < 500 像素的候选，SECOND 验证候选数降到 1/4（64 → 16），ΔF1 保住 94%；SYSU 验证降到 1/5，保住 82%。
   - H1 的分数排不出好候选：top-20 只拿到全量 H1 ΔF1 的约 13%（SECOND 验证 0.68 / 5.04，SYSU 0.41 / 3.17），曲线近似一条过原点的直线。H1 又是独有命中最多的来源（SECOND 测试 3785 个漏检对象只有它命中），所以要用 H1 就得全取，或者换别的排序。
   - C 的面积旋钮几乎不起作用（C 的候选本身多为大区域），单独贡献也最小。
2. **去重的代价（判断问题 2 的一部分）。** 四源并集去重后候选数降约 1/4（SECOND 测试 190 → 145，SYSU 测试 82 → 62），ΔF1_oracle 只损失 0.08–0.29 个百分点。但 R_obj@0.5 也随之下降（SECOND 测试 19.7% → 14.3%，SYSU 24.1% → 19.9%）：合并取并集让候选变大，和漏检对象的形状更对不上。D1 与 D2 的比较见第 3 步。
3. **对象召回与像素召回不一致（判断问题 5）。** 四源并集的 R_pix 在 SECOND / SYSU 测试上为 88% / 84%，R_obj@0.5 只有 14% / 20%。候选覆盖到了漏检像素，形状却对不上：G、B 的候选比漏检对象大，H1 的偏碎（Frag 1.5–1.6）。漏检对象的定义也有影响：SECOND 测试平均每图 26 个漏检对象，大多贴着检测器预测的边缘（第 3 步统计）。
4. **SECOND 验证 → 测试落差大。** 四源并集 ΔF1_oracle 从 9.25 降到 6.02，B 单来源从 6.31 降到 3.28。验证部分用的是交叉拟合检测器（F1 71.41，比测试低 2.8 个点），掩码外的漏检更多，B 能补的也更多。SYSU 的落差小（5.14 → 4.39）。第 5 步冻结工作点时要考虑这一点。
5. **SECOND 与 SYSU 的形状（判断问题 6）。** SECOND 上 B 和 H1 是主力、G 次之；SYSU 上 G 一个来源就占四源并集的 70%（3.64 / 5.14），B、H1 是补充。U5×4 在 SECOND 上高于四源对象并集（测试 7.31 vs 6.02），在 SYSU 上低（2.76 vs 4.39）：SECOND 的漏检需要切细的单元才能挑出纯的部分，SYSU 不需要。这与实验 7b “上限主要由单元粒度决定”一致，也说明两个数据集的差别首先在候选来源和粒度上，而不必是标签口径；后者本实验无法单独判断。
6. **LEVIR / WHU。** 四源去重并集中值得并入的候选只占 5.1% / 1.1%（Pos%），oracle 上界只有 +0.72 / +2.74。补漏在这两个数据集上空间很小，与 exp8 第 4 步“只需保证不伤”一致。
7. **来源取舍。** SECOND 测试上去掉 G 后 ΔF1 反而升 0.25（WHU 去掉 B、G 也略升）：G 的大连通域在去重时把别的候选并大、变得不纯。这是 D1 取并集带来的副作用，第 3 步的去重对比会检验。

## 第 4 步：不训练的排序规则

D1 去重后的四源并集上排序，截取每图前 K 个，或在整个划分上全局取前 N 个（N = K × 图像数，横轴同为平均每图候选数）。规则：
- r0：按真实新增像素精度降序（设计中的 oracle 参照）。
- **r0b（设计外补充）**：值得并入（精度 > F/2）的候选按新增真值像素降序排在前，其余在后。r0 不考虑面积，会先挑精度高但很小的碎块，所以不是 ΔF1 的上界（SYSU 验证 K = 8 时 r0 为 3.21，不训练的 r3 都有 4.18）。下面“与上界的差距”按 r0b 计算。
- r1：来源一致数降序，平局按新增面积升序。
- r2：新增像素内检测器平均概率降序。
- r3：第 2 步验证部分的来源优先级（SECOND B→G→C→H1，SYSU G→C→B→H1），同来源内按该来源自身分数（G 为检测器概率、B 为两期类别置信度乘积、H1 为 AnyChange 分数、C1 为 1 − 最佳匹配 IoU、C2 为特征距离；C1 与 C2 的分数刻度不同，直接混排）。
- r4：有 H1 分数的用 H1 分数的图内排名百分位，其余用 r2 的图内排名百分位。图内百分位不能跨图比较，全局版本只作参考。

## 第 3、4 步的回答

1. **去重是否误伤召回、D1 与 D2 哪个好（判断问题 2）。** D1 最好，D3（IoU 0.3）与 D1 几乎相同。D2 只留组内最小的候选，覆盖丢得多：全部候选时 R_pix 从 82–88% 降到 35–46%，ΔF1_oracle 降 0.5–2.7 个点（SECOND 验证 9.25 → 6.52，SYSU 验证 5.14 → 3.25）。D2 的 Frag 更低（1.6–1.7 vs 2.5–2.7），R_obj@0.5 略高（SECOND 测试 15.8% vs 14.3%），但抵不上覆盖损失。在有限预算下，D1 比不去重好得多：r1 截取时不去重的前几名几乎全是 < 100 像素的单来源碎块（K = 8 时 SECOND 测试 ΔF1 0.03，D1 为 0.62），因为没有去重就没有“来源一致数”这个信号。
2. **80% / 90% 需要多少候选（判断问题 3）。** 如果排序完美，每图 1–3 个（SYSU）或 3–8 个（SECOND）候选就能拿到 80–90%。最好的不训练规则需要：SYSU 验证 80% 约 8 个（r3 每图）、90% 约 20 个（r2 全局）；SECOND 验证 80% 约 30 个（r1 全局）、90% 约 80 个（r2 全局）。即不训练的排序比上界多用约 10 倍候选。
3. **哪个规则最接近上界（判断问题 4）。**
   - **小预算（每图 ≤ 8 个）时 r3 最好**：SYSU 验证每图只取 1 个就有 2.89（上界 4.15），取 3 个 3.74（上界 4.68）。这主要靠 G 来源排第一：SYSU 每图只有约 2 个 G 候选，而 G 一个来源就占四源并集的 70%。SECOND 验证 K = 8 时 r3 为 3.88，上界 8.63，差距大。
   - **大预算时 r2（检测器平均概率）最好**，它的 AP 也最高（混排 0.36–0.42，正例率 8–14%；r1、r3、r4 只有 0.10–0.24）。SYSU 验证全局取 20 个 r2 达 4.78（上界 5.14）。
   - **每图 top-K 与全局 top-N**：没有一致的赢家。r2、r0b 全局更好（概率可以跨图比较，难图多取、易图少取）；r1、r3、r4 每图更好（来源一致数、来源优先级、图内百分位在图之间不可比）。
   - 与上界差距最大的地方在小预算：SECOND 验证 K = 3 时，最好的不训练规则（r3）为 2.13，上界 7.51。也就是说，**不训练的分数能把有用的候选排到前面一部分，但远不够**：SECOND 上需要一个真正的评分器（第 6 步用 exp8 第 3 步已冻结的 V1 检验）。
4. **对象召回与像素召回（判断问题 5）。** 第 3 步再次看到两者不一致：D2 的 R_obj@0.5 略高、R_pix 大降；不去重的 R_obj 最高（K = 全部时 19.7% vs D1 14.3%），ΔF1 也略高。碎片指标在不去重（Frag 3.6–3.8）和 H1 参与时明显变差。R_obj 普遍低，主要是因为七到九成的漏检对象贴着检测区域边缘（见上）。
5. **验证 → 测试。** 排序规则的相对顺序在测试上保持（SECOND 测试 K = 8：r3 1.82、r2 0.88、r1 0.62，上界 5.50；SYSU 测试 K = 1：r3 2.36，上界 3.48）。

## 第 6 步第 5 项：漏检按四格拆分（不依赖评分器）

## 判断问题 7–9 的回答

**7. 后续流水线用哪些来源、哪种去重、哪个排序、每图多少候选？**
- 来源：保留 G0.05、B、H1。
  - B 最小面积 500 在两个数据集上都划算。
  - H1 在 SYSU 上要全取，SECOND 上取前 3 即可。
  - C 的独有贡献约为 0，档位也不起作用，可以不用；冻结工作点里的 C500 / C100 只是平局下的选择。
- 去重：D1。
- 排序：在没有更好的评分器之前用 r3（来源优先级）。
- 预算：
  - SYSU 每图 3–8 个，测试可拿到四源 oracle 上界的 74–83%，MLLM 全测试集预算 1.4–3.6 GPU 小时。
  - SECOND 每图 8–20 个，测试只拿到上界的 42–64%，预算 1.7–4.1 GPU 小时。
- 但第 6 步说明，瓶颈不在候选，而在判断：现有 V1 和检测器概率在这些候选上都守不住 F1（SECOND），或几乎不补无信号漏检（SYSU）。所以这些工作点更适合作为交给 MLLM 或新评分器的输入，而不是交给现有 V1。

**8. 真实评分器下，ΔF1 ≥ −0.3 时漏检率最多能降多少？验证到测试是否保持？**
- SECOND：验证最多 −8.70 个点（34.11% → 25.41%，U5 + clean）。冻结到测试后漏检率降 11.40，但 ΔF1 为 −4.22，**没有保持**。所有方案在测试都越过了 −0.3。
- SYSU：验证最多 −2.80（19.36% → 16.55%，U5 + clean）。测试 −2.09，ΔF1 −0.34，**基本保持**。U5 + detector 为 −1.74 / −0.22，完全在约束内。

**9. 四格各占多少漏检？①+② 漏检率降了多少，ΔF1 是否保住？SECOND 与 SYSU 是否不同？**

- ①+② 漏检率，ΔF1 ≥ −0.3（验证选阈值）时：
  - SECOND 验证最多 −2.63（16.56% → 13.93%），但测试 ΔF1 守不住；
  - SYSU 验证 −0.36（4.96% → 4.60%），测试 −0.39，ΔF1 −0.34。

  - SECOND 的 ①+② 占比大、oracle 对象召回低（20%），真实评分器补到的比例相对较多，但 F1 迁移失败；
  - SYSU 的 ①+② 占比小、oracle 对象召回较高（42–47%），却几乎补不上：候选里有，评分器不接受。
