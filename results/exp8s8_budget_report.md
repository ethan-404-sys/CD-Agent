# 实验 8 补充 8：开跑前的问题报告（LEVIR、WHU 补漏流程）

日期：2026-10-27。任务原文：`doc/exp8s8_levir_whu_pipeline.md`。

本文只做清点与估算，没有运行检测器、SAM3 或任何训练。清点由 Codex 只读服务器上的代码、日志和缓存完成，我核对后整理。数字都有来源。凡是没有实测的，下文都写明“推算”。

## 结论：按原设计交叉拟合会超出 24 GPU 小时，已停下

1. **检测器交叉拟合是唯一的大头，GPU 小时没有实测依据**：
   - 候选生成（SAM3 语义、SAM ViT-H 自动掩码、检测器推理）按已有实测计时外推，新增约 1.1 GPU 小时。加余量后取 2.5 小时。
   - 用本地预设的 SChanger 训练配置做 K=4 交叉拟合，需要约 300–440 GPU 小时，原因有两点：
     - 预设轮数很长：LEVIR 12000 轮，WHU 1000 轮；
     - 每优化步耗时按 0.4 秒推算。服务器上找不到 SChanger 训练的计时记录，所以这个数字只是推算。
2. **缺干净的初始化权重**：SChanger 训练默认从“建筑分割预训练权重”开始，服务器上没有这份权重。服务器上只有 6 份已经在各数据集上微调过的发布权重。从 LEVIR 或 WHU 的发布权重继续训练各折不行，因为这些权重已经见过留出折的图，折外预测就不再是“没见过”的。
3. **WHU 划不出空间独立的验证部分**：
   - WHU 的 1,260 张训练图是 512 切块，文件名是 `train_0` 到 `train_1259`。
   - 数据目录和预处理脚本里都没有切块在原始大图中的坐标、行列数或遍历顺序。
   - 按图随机划分，相邻切块可能一个在训练、一个在验证，造成空间泄漏。
   - 还有一个问题：新验证部分来自官方训练区域，官方权重可能训练时见过这些图。所以文档规定“验证部分用官方权重”时，阈值选择会偏乐观。

## SECOND 的交叉拟合能否照搬

`second_cv` 的做法：
- K=3 折，每折 50000 步，检测器是 MambaSCD-Base。
- 只用 ImageNet 预训练初始化，从没用过见过 SECOND 训练集的权重。
- 3 折共 176 GPU 小时，每折用 2 张 A800。

划分清单、折外预测格式和“只用外折以外的内部验证选 checkpoint”这套原则可以照搬。但训练实现和耗时不能照搬。

另外，交叉拟合也不保证分布一致：SECOND 训练折外 F1 是 71.0，测试是 74.2；每图 G0.05 候选数是 90 对 219。

## 低成本方案（供讨论，未启动）

固定 SChanger-base、LEVIR U5_x16、WHU 直接对合并。下表中“推算”一列按每步 0.4 秒、含 20% 余量；括号内是每步 0.8 秒的情形。

| 方案 | 推算 GPU 小时（检测器 + 候选） | 风险 |
|---|---:|---|
| A. 下载 SChanger 建筑预训练权重，K=4，各约 100 轮 | 6.8 + 2.5 ≈ 9.3（16.2） | 训练轮数远少于预设，检测器可能欠拟合，训练折的漏检会比测试多 |
| B. 同 A，各约 200 轮 | 13.7 + 2.5 ≈ 16.2（29.8） | 0.8 秒/步时超预算 |
| C. K=2，各约 200 轮 | 4.5 + 2.5 ≈ 7.0（11.6） | 每折只用约一半训练图，漏检更偏多 |
| D. 只做 1 折折外预测，约 75% 的图训练更久（各约 1000 轮） | 17.1 + 2.5 ≈ 19.6（36.6） | 判断器训练样本只有约 1/4 的训练图 |
| E. 改用 SChanger-small | 训练速度未实测 | 训练折与测试池的检测器不同，概率校准和漏检对象都会变 |

**我的建议**：
1. 先下载预训练权重，并确认它没有用过 LEVIR、WHU 的数据。
2. 在 Slurm 上做一次约 0.3 GPU 小时的短训练，实测每步秒数。
3. 把实测值代入上表，在 A 和 D 之间选，选择只看验证部分的漏检分布。
4. 用验证部分比较折模型与官方模型的 ①②③⑤ 比例、② 对象数、G0.05 候选量和概率分布，回答文档的判断问题 4。差距大就如实报告。
