**第 4 轮优先检验 B 的大近景限制：核实通过后，近景边长达到 512 像素的候选暂不加入。** 在第 3 轮选中的 A/B 配置上，这个单因素缓存回放使 B 的累计 F1 在 k=10/20/50 分别变化 **0、+0.065、+0.250** 个百分点。它比单纯提高 P(yes) 门限更有针对性，但 k=50 只涉及 3 张图的 5 个候选，尚未验证修改后的 C，当前是下一轮候选方案，不能当作已确认的最终收益。

**后续优先级：B 队列 20→50、核实提示、C 仅修有肯定核实证据的区域、T7 换 SAM3、换初始化。** 队列扩展的预算内机会比全局覆盖曲线显示的小；其余方案都缺少同口径的完整验证集结果。以下结论、阈值和顺序全部依据验证集，未读取本轮测试集掩码或用测试集选参。

文中 F1、IoU 以百分数表示，差值用百分点；`RUN` 为任务指定的 `../ovcd_v0_run`。验证集共 64 张图，所有预算共享 M0，初始累计 F1 为 **57.822896**。本次仅在当前目录新增本文；外部实验产物与实现均只读。

**1. B 接受候选中的误检：先分清候选与实际新增像素**

对每条 `candidate_mask` 写入，解码原候选 Q，并从保存的 A 掩码开始按轨迹重建当前 M；实际新增部分为 `Q & ~M`。用验证集真值 G 分别统计：

- **完全误检候选**：`|Q ∩ G|=0`。这是本文“完全误检”的严格口径。
- **新增 TP 为零**：候选可能与真值相交，但真值部分已被当前 M 覆盖，因此本次写入只有 FP。
- **诊断中的 not useful**：既不满足候选自身至少 50% 落在真值上，也不覆盖某个 M0 整目标漏检至少 30%。沿用 `diag_mllm.py` 的标签；它不等同于完全误检。
- **相对 A 不利的写入**：新增像素精度低于该预算 A 的累计 F1/2。这是把该次新增部分单独加到 A 的计数时的收益界线，不等同于轨迹记录的单图 F1 下降。

|---|---:|---:|---:|---:|---:|---:|---:|
| 10 | 211 | 28 | 2（7.14%） | 2 | 3 | 3 | 24,360 / 11,283 |
| 20 | 561 | 87 | 14（16.09%） | 16 | 18 | 19 | 68,876 / 50,264 |
| 50 | 1,079 | 213 | 40（18.78%） | 45 | 54 | 57 | 161,769 / 156,370 |

三档接受集合按“图名、uid”去重后共有 **213** 个候选，恰好等于 k=50 的接受集合。以下候选特征统计都以这 213 个为单位，不把同一候选在不同预算下重复计数；新增像素统计使用 k=50 的实际执行状态。

完全误检候选在 k=10/20/50 分别新增 **3,978 / 22,463 / 78,738 FP**；k=50 的 40 个完全误检分布于 28 张图，贡献 B 新增 FP 的 **50.35%**。54 个 not useful 候选合计只新增 **397 TP、95,446 FP**。因此去掉 T5 解决了掩码生成失控的问题后，核实通过的候选本身仍有明确的误检损失。

213 个候选中，Qwen 类型为 `new_building` 209 个、`demolished` 3 个、`rebuilt` 1 个。40 个完全误检中，**39 个被回答为 new_building，1 个为 demolished**；54 个 not useful 中，53 个为 new_building，1 个为 demolished。没有可直接按 `shadow`、`seasonal_or_color` 等模型输出类型剔除的已接受误检。这里的类型是模型回答，尚未人工确认错误实际来自阴影、时相差异还是建筑识别错误。

P(yes) 是 yes/no token 的归一化概率，未证明是候选正确率的校准估计。原验证网格中，k=20/50 把 τB 从 0.90 提高到 0.95，B F1 反而从 **58.872/59.964** 降至 **58.799/59.925**；新排序下也分别从 **59.850/60.651** 降至 **59.778/60.617**。因此保留每档网格选出的阈值，不能仅凭高置信误检存在就统一提高门限。

**M-C-I 属性可以辅助排序，单独硬过滤的证据较弱。** 在已接受集合内，以完全误检为正类，使用低 P(yes)、低 p_own、高 p_other、低 score、大面积、大近景预测误检的候选等权 AUC 分别为 **0.745、0.623、0.604、0.541、0.515、0.577**。这些是筛选后的 213 个候选上的描述性统计，与原来 1,279 个 B 候选上 useful AUC=0.942 的标签和样本范围均不同。

其中 **198/213** 个接受候选的 p_own<0.5，包含 37 个完全误检，也包含 161 个与真值相交的候选；它们贡献了 **152,227/161,769=94.10%** 的新增 TP。T7 本来就在寻找未通过原 M-C-I 硬门限的候选，重复要求 p_own≥0.5 会消除主要的补充机会。

**2. 可直接执行的 B 单因素建议与边界**

本次进行了动态 A/B 回放：固定选中 τA、τB，核实仍消耗一次调用；通过 τB 后再执行候选过滤；过滤会影响后续覆盖判断，因此后续候选重新遍历。没有重新选择阈值，没有运行修改后的 C。表中是阶段 B 的累计 F1：

| 条件 | r2 k=10 / 20 / 50 | r3 k=10 / 20 / 50 |
|---|---|---|
| 原流程 | 58.318 / 58.872 / 59.964 | 59.284 / 59.850 / 60.651 |
| 拒绝近景边长 ≥512 | 58.318 / 58.934 / 60.207 | 59.284 / 59.915 / 60.900 |
| 拒绝候选面积 ≥3,000 | 58.306 / 58.928 / 60.158 | 59.272 / 59.911 / 60.855 |
| 仅保留 p_own≥0.5 | 57.953 / 57.992 / 58.194 | 58.914 / 58.955 / 58.884 |

下一轮建议将 **`crop[2]-crop[0] >= 512` 时不加入候选**作为单独流程因素，位置放在 B 核实之后，维持现有预算计算；仍用同一验证网格选择 τA、τB、C 模式与门限，同时保留“不加此限制”的对照。暂不同时改面积阈值、提示或队列长度，以便识别收益来源。

512 来自本次验证集尺度分组，尚未独立验证。k=50 的 5 个候选只来自 val_15、val_16、val_33；k=20 只拒绝其中 1 个，k=10 没有触发。需逐图报告移除 TP/FP，并以完整 C 的累计 F1、对象指标和逐图结果验收。若 C 后 F1 收益消失，应放弃该限制；对象指标的变化也需单独解释。另一个后续方向是调整大区域的近景方式再核实；这需要新的图像输入和调用，当前缓存不能给出效果。

**4. 第 4 轮及以后：逐个因素的证据和缺口**

**优先 1：B 大近景限制，作为第 4 轮候选。** 上文已给出实际缓存回放、明确执行位置与完整流程验收要求。保留 r3 的排序，不同时改变视觉输入。主要缺口是 C 后结果和小样本稳定性。

**优先 2：B 队列 20→50，但先承认预算限制。** 现有 `val_queue_diag.json` 中，1,203 个 M0 整目标漏检，前 20 项覆盖 253 个（21.03%），前 50 项覆盖 405 个（33.67%），多 152 个；真值决定加入哪些候选的参考 F1 从 61.595 提高到 63.317。该参考使用 M0，不受实际核实预算约束，也不包含 A/C。

本次逐图连接队列、M0 真值漏检与 r2 的实际调用量后得到：

- k=10/20 的每张图都已用满预算，单独扩展队列不会访问第 21 项以后。
- k=50 有 34 张图剩余调用，共 718 次；新增覆盖的 152 个目标中，仅 **24 个**位于这些图上，分布在 11 张图，另外 128 个位于已用满预算的图上。
- 在这 34 张图上，按保存的 B 掩码检查，第 21–50 项有 949 个候选未被覆盖，最多可安排 648 次额外调用。若保持 B 掩码不变、沿原队列取余额允许访问的前缀，这些候选仅触及 **13 个**前 20 项没有覆盖的 M0 漏检目标。
- 第 21–50 项共 1,830 个现成候选，**已有核实缓存为 0**。

13 是“冻结当前掩码、不执行新写入”的可访问机会统计；新写入可能影响覆盖跳过，A 又可能产生新的漏检，真实像素收益不能由这一个数字推出。若后续试验只扩 b_max，应保持调用预算、A 份额和核实规则不变，单独报告第 21 项以后实际访问数、新增 TP/FP、对象命中和 C 后结果。降低 A 份额可增加访问机会，但属于另一个因素，不与扩队列一起归因。由此，扩队列仍值得测，却不再凭“多覆盖 152 个”就排在有实测收益的大近景限制之前。

**优先 3：修改核实提示，先明确要判定的对象。** B 的 40 个完全误检中 39 个被说成 new_building；A 的 887 个“按像素收益宜删”候选中 418 个被回答为 new_building，说明肯定回答与实际操作收益之间存在差距。现有提示问“轮廓内是否有建筑变化”，少量真实变化就可能满足字面问题，但不足以支持整块保留或整块加入。

候选试验应固定建筑新增、拆除、重建的任务定义，只改变核实要求：分别核对同一位置在两期的建筑证据，并说明红色候选区域是否主要对应该变化。A 和 B 的操作目标需分开表述；B 还可另行检验标出当前预测未覆盖部分的输入。新的提示或输入需要重新获得验证集回答，比较新增像素精度、误删 TP、完整 F1 与调用成本；没有这些结果，不能宣称“加几句口径说明”会超过排序或过滤。真实误判原因尚未人工分型，已有口径卡本就列出了阴影、季节、配准和非建筑变化。

**优先 4：C 只修有肯定核实证据的区域。** 该建议有研究动机，但已有验证集不支持直接认定它会更好：

对象数变化可能来自拆分、合并及匹配方式，不能直接与像素计数互换。C 当前对进入阶段时的所有连通域执行 SAM 修补，门限约束的是新旧掩码 IoU，未检查语义核实。

为定位范围，本次把“A 中已访问、保留且 P(yes)≥0.5 的掩码”和“B 接受的候选掩码”取并集，检查其覆盖 C 入口连通域的比例。k=50 的 2,097 个入口连通域中，1,262 个至少一半像素有上述肯定证据，832 个完全没有，3 个仅有少量覆盖。没有肯定证据的 832 个中，C 接受修补 799 个，其中轨迹单图 F1 上升 440 次、下降 341 次、其余持平；多数像素有肯定证据的 1,262 个中，接受 1,171 个，上升 635 次、下降 528 次。不能把这些次数换算成累计收益，它们表明“未经核实的修补全部无益”缺少依据。

若进行此项试验，需要定义 A/B 掩码合并后新连通域的核实证据如何继承；可以预先固定“至少一半像素有肯定证据”作为可执行候选定义，未覆盖区域维持 B 状态，并保留原 C 门限。这个 50% 尚未选优。缓存没有保存每一次 C 的替换掩码，本次未重新运行 SAM，因此没有选择性 C 的精确反事实。若为全部 C 连通域补充 T3，会改变调用预算，须单独实验。

**优先 5：T7 换 SAM3。** 现有来源前 50 项仍只覆盖 M0 整目标漏检的 33.67%，候选来源确有不足。缺少 SAM3 在同一验证集上的候选覆盖、掩码精度、与原 T7 的新增互补覆盖、核实通过质量及预算内最终结果。先固定初始化和 A/B/C 策略比较来源，报告前 20/50 项、实际可访问前缀和候选生成成本，再决定替换；不能直接把新模型的名字当作改善依据。

**优先 6：换初始化。** M0 的累计精度为 47.782%、召回率为 73.206%，有 2,253,033 FP、754,602 FN；FP 占全部错误像素的 74.91%。其中 1,557,370 FP 落在与真值命中的预测对象上，提示整块删除难以完全解决边界或混合区域问题。验证集按真值选择整块删除的参考 F1 为 65.427，当前初始状态仍有可利用空间，因此先完成有明确证据的现有流程调整。

替代初始化尚无同一验证集结果。切换后 M0、A 连通域、B 候选与核实输入都可能改变，旧调用缓存和本轮阈值不再能直接比较。应分别报告新 M0、本身成本、错误构成和相同预算下完整流程，按新验证集网格选参；这项改动范围最大，放在后面。
