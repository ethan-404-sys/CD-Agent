上限使用代码的 `round(a_share*k)`，所以 0.75 对应 38，0.65 对应 32。0.60 已确保每图至少留出 20 次 B 调用，正好覆盖现有全部前 20 项；继续降低 A 份额不会新增 B 访问，只减少 A 的机会。该结构也给出了选择 0.60 的具体理由。

相对 r6，0.60 少做 **195 次 A**、多做 **150 次 B**，总调用从 **2,259 降到 2,214**，每图均值从 35.296875 降到 34.593750。A 少删的部分保留了 **1,840 TP、6,899 FP**，使 A F1 下降 0.043408；新增 B 访问实际补入 **15,248 TP、9,569 FP**。最终净增 **17,088 TP、16,468 FP**，得到 **TP=2,432,992、FP=1,265,563、FN=383,276**，IoU=59.605407、精度=65.782231、召回=86.390642。接受 B 项数从 256 增到 314。

实际访问②覆盖从 80,947 增至 **91,123**，整目标触及从 105 增至 **127**。相对 r6 的最终 F1 增益逐图留一范围为 **+0.095798～+0.165439**；最小值对应排除 `val_27`，最大值对应排除 `val_9`。主要正贡献来自 `val_27/15/28/43`，负贡献较大的是 `val_9/21`。这项改动的增益来源与 r6 主要依赖 `val_44` 的现象不同，但仍只是同一验证集上的探索结果。

**不统一修改三档预算。** 若 k=10/20 也设为 0.60，冻结原 τB 与原网格重选均得到 **73.544167 / 74.031977**；k=20 比 r6 下降 0.089954。因此建议只改 k=50 的预算份额，小预算维持原配置。

**5.2 b_max 从 20 扩到 50：所需新调用与预算内机会**

r6 保存前 50 项共 1,864 项，其中前 20 项的 978 项均有回答，排名 21–50 的 **886 项均缺回答**。若统一补齐整份前 50 缓存，需要 886 次新核实；若仅满足现有 k=10/20/50、`a_share=0.75` 的实际可访问项，则只需要 **237 次**，全部来自 k=50 的 **22 张图**，三档共享这些新增回答。

| k | b_max=20 的 B 访问 | b_max=50 的 B 访问 | 新核实数 | 扩展后的②覆盖 / 整目标触及 |
|---|---:|---:|---:|---|
| 10 | 144 | 144 | 0 | 5,738 / 12，完全不变 |
| 20 | 357 | 357 | 0 | 36,834 / 47，完全不变 |
| 50 | 828 | 1,065 | **237** | **90,070 / 117** |

这里“所需新调用”可精确计算：SAM3 候选互斥且不碰 M0，B 的接受门限不会改变访问或覆盖跳过；每图访问数为 `min(队列长度, k−min(A长度, round(0.75*k)))`。k=10/20 永远访问不到第 21 项，最终 F1 也保持 r6 不变。

k=50 的新 237 项共含 **9,143 TP、58,715 FP**，新增②覆盖 **9,123**，多触及 12 个整目标漏检。缺少它们的模型回答，所以不能给出真实最终 F1。为衡量这批额外候选的空间，固定既有 A 和前 20 项决策，只对新增候选借真值选最优完整掩码子集：按真实像素精度排序扫描最优前缀，最佳接受 10 项，F1=**74.706072**。候选互斥、调用集合固定，故这是这批新增整候选在固定旧决策下的最优参照；若进一步允许逐像素去掉全部 FP，F1=**74.727077**。这些参照均使用真值，不能当作核实模型的预期成绩。与已有的 74.690958 缓存收益相比，它们尚不足以让扩大队列成为首选。

**5.3 两来源合并：互补仍在，简单合并仍不优于 r6**

旧来源使用 r4 的 M-C-I 候选与原回答，新来源使用 r6 分块 SAM3。集合并集的覆盖如下，整目标列按“触及对象集合”合并；尚未施加共同调用预算。

**5.4 更小的 256² 分块：保留为后续来源实验**

验证集两期共有 128 个整图输入，512² 需要 **512 个分块时相输入**，256² 则需要 **2,048 个**。这是分块输入数增加到四倍，耗时不必严格四倍。若保持每图前 20 项核实，新的 B 输入至多需要 **1,280 次**核实，准确数量取决于新队列；A 可继续复用。新分块会改变掩码、分数、连通域和近景，不能按旧 uid 复用 B 回答。

当前并集对中、大对象已覆盖较好，合格池到前 20 项的②损失更大；256² 还可能改变跨块建筑和接缝差异。因此优先完成现有缓存支持的预算调整。本文未运行 256² 分割，也没有给它推测性的 F1。

**7. 六轮里验证集与既有测试集都支持的结论**

这里只核对已有 `RUN/eval/r{1..6}_k{10,20,50}_{val,test}.json`，表内依次为 k=10/20/50 的最终累计 F1。

| 轮次与主要变化 | 验证集 | 测试集 |
|---|---|---|
| r1 原流程 | 58.402 / 58.374 / 58.260 | 54.006 / 51.145 / 50.911 |
| r2 关闭T5、直接补候选 | 58.538 / 59.093 / 60.226 | 54.223 / 54.669 / 55.268 |
| r3 A改score_asc并按原规则选门限 | 59.472 / 60.035 / 60.883 | 54.635 / 55.262 / 55.969 |
| r4 I-M-C初始化及队列适配 | 73.500 / 73.600 / 73.550 | 70.096 / 70.172 / 70.142 |
| r5 SAM3整图两期差异 | 73.581 / 73.600 / 73.615 | 70.107 / 70.172 / 70.487 |
| r6 SAM3 512²分块 | **73.540 / 74.122 / 74.550** | **70.226 / 70.539 / 71.374** |

1. **初始化仍是六轮中最大的性能变化来源。** M-C-I→I-M-C 的 M0 从验证集57.823升到73.008、测试集53.759升到69.670，分别增加15.185、15.911。r4完整流程还包含队列适配与A排序选择；M0自身的变化足以支持初始化的重要性，不能把它算成Agent增益。
2. **旧M-C-I流程中，关闭T5并直接加入核实后的候选，三档均获两划分支持。** r2相对r1的最终F1，验证集提高0.136/0.719/1.966，测试集提高0.218/3.524/4.358。这项流程改动同时影响写入形状和可用核实次数，结论应保留这一范围。
3. **旧初始化中，A改为score_asc并按原规则重选门限，收益延续到完整流程。** r3相对r2，验证集提高0.934/0.942/0.657，测试集提高0.412/0.593/0.701。它适用于当时来源和初始化；r4以后k=50选择area_asc，不能将score_asc写成普遍最优排序。
4. **I-M-C上的A提供较小但跨划分一致的累计增益，更多预算没有保证A更好。** r4–r6相同的A相对M0，验证集提高0.492/0.593/0.542，测试集提高0.426/0.503/0.472，两划分均为k=20高于k=50。各预算的排序和门限也不同，不能单独归因为调用数。
5. **SAM3来源已使B在I-M-C之上获得跨划分正收益，512²的主要进一步收益出现在k=20/50。** r5相对r4，验证集为+0.081609/0/+0.064826，测试集为+0.010985/0/+0.345032；r6的B相对共同A，验证集为+0.040310/+0.521755/+1.000390，测试集为+0.130005/+0.367391/+1.231804。已有证据可从“部分预算有微小补入”更新为“分块后中、大预算有较明确的累计补漏收益”，仍需同时报告误检和图间差异。
6. **512²相对整图的改善有预算条件，不能写成三档一致提升。** r6相对r5，k=20/50在验证集分别提高0.521755/0.935563、测试集提高0.367391/0.886772；k=10则是验证集下降0.041300、测试集提高0.119021。两划分支持中、大预算的改善。r6最终分数随k增加而提高，但配置也在改变，尚未证明固定配置下增加预算必然有效。

“更小分块一定继续提高”“两来源合并有效”“a_share=0.60能在测试集提高”尚没有双划分证据。C在当前验证网格支持关闭，测试集只评了选中的关闭配置，也不能据此宣称开启C在测试集必然无效。
