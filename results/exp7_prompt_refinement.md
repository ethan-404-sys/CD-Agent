## 7b：判断单元对比（oracle，2026-10-22）

**设定**
- 候选来源固定为 B+G0.05+H1，只更换判断单元。
- oracle 口径：单元内真值占比 ≥ 50% 才并入，与现有口径相同。
- 选择在 SECOND 交叉拟合验证集上做（297 张）。测试集（1,694 张）每种单元只评一次。
- 单元可能互相重叠，去重在 oracle 判定之前完成，不使用真值。规则：按单元面积从小到大排序，先排到的单元占用像素；后面的单元扣掉已被占用的部分，扣完为空就删除。
- U0 去重后，部分切块的形状会改变。因此另列一行 U0_pool：直接用原池切块及其标签，与历史 oracle 核对。

**各单元的做法**
| 单元 | 做法 |
|---|---|
| U0_pool | 6a 原切块池，不去重（历史 oracle 口径，V1 现在用的单元） |
| U0 | 同一批切块，经上述去重 |
| U1 | SLIC，请求面积 150，compactness 10 |
| U1low | SLIC，请求面积 298，compactness 1（低紧凑度，更贴颜色边缘） |
| U2 | SLIC，请求面积 600，compactness 10 |
| U3 | 不切细，直接用原始候选区域 |
| U4 | SAM ViT-H 自动掩码（默认参数），t1、t2 各做一次，两期标签的共同细分再与候选求交。两期都没有掩码覆盖的像素不构成单元 |

SLIC 只切面积大于 4 倍请求面积的候选，因此实际面积中位数小于请求值（见下表）。

- U0_pool 的测试 F1 82.67 与历史 5c 的 BGH1 oracle 一致，口径核对通过。
- 按验证集像素 F1 排序：U1 > U1low > U0 > U0_pool > U2 > U4 > U3。测试集顺序相同。
- **U1 是上限最高的单元，但领先很小**：测试比 U0_pool 高 0.91 个点，比 U0 高 0.58 个点。代价是每图单元数是 U0_pool 的 1.7 倍。单元越小越难训练，所以这 0.6–0.9 个点的上限不一定能转化为实际收益。
- 去重本身带来 +0.33（U0_pool → U0）。原因：去重后重叠部分被拆开，单元变小。这不是新方法，只是粒度变细的另一种形式。
- **对象级单元在 oracle 下不占优**：
  - U3 不切细，比 U0_pool 低 3.17 个点。这与 exp8 的去重统计一致：不切细时上界只有 +4.8 到 +5.3。
  - U4 用 SAM 自动掩码切分，比 U0_pool 低 0.97 个点。主要原因是覆盖率下降：两期都没有 SAM 掩码的像素被排除，无信号漏检像素的覆盖从 69.2% 降到 61.3%。
- 低紧凑度的 U1low 只比 U0 高 0.12 个点。它与 U0 面积相近，说明更贴颜色边缘对像素 F1 的作用很小。

- 边界指标的排序与像素 F1 基本一致，U1 同样最好。
- “无信号目标覆盖”沿用 6a 的口径：单个候选覆盖目标 ≥ 50%，且单元面积不超过目标外接框 4 倍才算找到。单元越细，单个单元越难覆盖整个目标，所以这一列随单元变小而下降。它不代表召回下降；像素覆盖几乎不变就是证据。
- U0 及其他去重后单元的“新增误检目标”比 U0_pool 多。原因：去重后留下的小残片单独成为单元，oracle 只按占比并入，残片在真值边缘外形成小误检。这只影响目标计数，像素 F1 仍然更高。
- U4 的耗时包含 SAM 自动掩码的 GPU 时间，两期合计约 3.1 秒/图。验证集 U4 作业总用时约 18 分钟（297 张），测试集约 1.7 小时（1,694 张）。

### 判断问题 5 的回答
- **像素 F1 上限由单元粒度决定**：U1 细切最高（83.58），不切细最低（79.50），两者差 4.1 个点。SLIC 参数（紧凑度）和对象级切分的作用都小于粒度。
- **SLIC 不需要换成对象级单元**：在本实验的 oracle 下，SAM 对象级单元（U4）比现有切块低约 1 个点，原始候选（U3）低约 3 个点。
- 这个结论只针对 oracle 上限。实际验证器在细单元上是否更难训练，要等 V1 重训才能回答。
- **V1 在新单元上重训：未做**。文档把它列为可选项。U1 的上限领先不到 1 个点，而单元数多了 70%。Ethan 也判断过单元越小越难训练。因此本轮不做，留待确认。

### 与实验 8 的关系
exp8 的设计以对象级单元为主（Ethan 确认），而 7b 显示 oracle 上限主要由粒度决定。两者并不矛盾：exp8 关注的是验证器在噪声标签下能否学好，7b 只给出 oracle 上限。但 exp8 的对象级池在 oracle 下比 SLIC 切块低约 3–4 个点，这个差距需要在 exp8 的结论里一并报告。

## 提示精修（降为低优先级，2026-10-22）

### 做了什么
- **确认区域**：通过确认的切块合并成连通域。O 设定由切块级 oracle 确认（B+G0.05+H1）；V 设定用 V1 none 确认，阈值 0.820。精修只作用于确认区域，检测器原预测不动，去误检一侧不精修。
- **网格**：在 SECOND 交叉拟合验证集（297 张）上跑全网格：
  - 提示方式 P1–P7；
  - 两个模型：SAM3、SAM ViT-H；
  - 期次三选：t1、t2、两期中分数高的（best）；
  - 合并方式五种：替换、与确认区域外扩 3/5/10 像素取交（clip3/5/10）、取并；
  - 另加非提示对照：P0 不精修、软边界、开闭运算。
  - 共 213 种配置。
- **冻结方案**：按原 batch16 规则在验证集冻结，O 设定 9 种、V 设定 17 种。测试集（1,694 张）每种只评一次。原规则先按“像素 F1 不降超过 0.3”筛选，再按边界指标排序。
- **未做（降级）**：SYSU、LEVIR、WHU。导向滤波也未做，因为服务器没有 `cv2.ximgproc`。

### 判断问题 1–4 的回答
1. **O 设定**：
   - 像素 F1 与 P0 相比不降超过 0.3、同时边界改善的方案有两种：sam3 P4（掩码提示）和 sam_vith P4，测试 ΔF1 分别为 +0.27 / +0.11，ΔBF2 为 +0.66 / +1.07。
   - 但改善都很小。粗糙度只从 2.69 降到 2.63–2.64。
2. **V 设定**：
   - 精修**缩小了误检像素**。以 sam3 P3 为例，FP 像素从 3,117 万降到 2,641 万；像素 F1 +0.87。
   - 但每图新增误检目标从 0.7 个增加到 5.9 个：错补区域被切碎，而不是被删掉。
   - 逐图下降比例从 62.8% 降到 57.0%。V1 本身的主要问题（过半图像变差）没有解决。
3. **按类型 / 面积**：
   - SAM 只适合小于 1,000 px 的区域和拆除类。对大面积成片变化（地表、植被）和改建基本无效。
   - 如果以后要用精修，应该按面积决定是否精修：大区域保持整块并入。
   - 新建与拆除分别用哪一期影像更好：验证集已有逐区域记录，补算如下（2026-10-22）。总体结果：O 设定 sam3 P4 的验证 F1 为 best 82.05、t2 82.03、t1 81.93。
   - 新建类用 t2 更好，拆除类用 t1 更好：建筑在哪一期出现，就用哪一期提示。其余类型两期相差不到 1 个点。“best”（取 SAM 分数高的一期）在两类上都接近较好的一期，因此不必按类型指定期次。
