改了什么

首轮。

A

M0

做了什么

用 DynamicEarth 官方 M-C-I 代码与参数在 LEVIR 1024² 全图上推理，不改任何决策，另外导出每个 SAM 提议（每图约 600 个）的 DINOv2 变化分数、两期 building 概率和是否进 M0。3 张验证图上官方流程与导出流程逐像素一致；每图约 7.2 GPU 秒。

得到了什么结果

测试集 F1^c 53.76、IoU^c 36.76（原文 53.6 / 36.6，差 0.16），P 45.75、R 65.16。验证集 F1^c 57.82。I-M-C（APE-DINO）的环境本轮没跑通，图中只列原文数字。

遇到的关键问题

  • 官方 SegEarth-OV 的上采样器保留 Dropout，输出带随机性；我们按图固定种子。
  • 网络慢：权重改从 ModelScope 下载并按 HF 的 sha256 核对；CLIP ViT-B/16 用 timm 发布的同一份 OpenAI 权重（已核对 fp16 无损）。
  • I-M-C 需要 16 GB 权重和 detectron2/detrex 编译，环境第一次因 detrex 的 omegaconf 版本冲突失败。

下一步怎么做，为什么

用这份 M0 和逐提议分数做 M1 错误分析；I-M-C 环境修好后补对比行。

B

M1

做了什么

在验证集（选择）和测试集（描述）的 M0 上统计整目标漏检/误检率、误检像素构成、漏检像素的 ①②③⑤ 格（沿用 miss_share 定义，基准为 M0）、理想删除与理想补入的上限；在验证集上比较阶段 A 的六种排序（理想核实下的删除收益曲线）和 T7 候选覆盖率。

得到了什么结果

  • 整目标漏检率 验证 43.1% / 测试 50.5%；整目标误检率 38.2% / 39.3%。
  • 误检像素占全部错误 75% / 69%，但其中约 70% 是命中目标外多出的像素，整块误检只占约 30%。
  • 漏检像素 69% 是 ② 孤立无信号。
  • 理想上限（验证）：A 删除最优集合 65.43（+7.6），B 补回整目标漏检 69.85（+12.0）。
  • 排序：按面积从大到小最好（每图查 15 个：62.97）；小连通域更常是误检（AUC 0.88），但删掉它们挽回的像素少。
  • T7：前 20 个候选只命中 21% 的整目标漏检，前 50 个 34%。

遇到的关键问题

误检大部分是边界外溢，A 删整块只能处理三成；漏检主要是 M-C-I 根本没出提议的目标，T7 的近阈值提议只覆盖五分之一。

下一步怎么做，为什么

A 用面积降序；按误检像素占比把 75% 预算给 A。

C

M2

做了什么

每个 M0 连通域：T2 近景（外接框 4 倍、384²、红色轮廓）→ T3 Qwen3.5-4B 核实（系统提示放口径卡，回答是否、伪变化类型、一句理由，读 yes/no 概率）→ P(yes) < τ_A 则 T4 删除。τ_A 在验证集上按 k 分别选。

得到了什么结果

  • MLLM 判别力：P(yes) 区分该删/该留的 AUC 0.85，按面积加权只有 0.69。
  • 验证集 τ_A 曲线几乎平坦（0–0.7 之间 57.6–58.0）；选中 0.2 / 0.1 / 0.5。
  • 验证集 A 相对 M0：+0.10 / +0.10 / +0.21；测试集 +0.02 / 0.00 / −0.19。
  • 逐图平均 F1 在测试集上 +1.6–1.9，主要来自空真值图上的误检被删光（单图 F1 从 0 跳到 1）。

遇到的关键问题

按面积降序先核实的是大块、精度中等的连通域，Qwen 看到里面有建筑就答“是”；判别力恰好在像素权重大的地方最弱。k=50 测试集删除的像素中真阳性占 29.7%，高于 F1/2，累计 F1 因而下降（例 test_27 uid 19，精度 58%，被判 no_change 删除）。

下一步怎么做，为什么

Codex 用缓存精确核算：A 改按 M-C-I 变化分数升序并重选 τ_A，验证集 A 可到 58.88（k=20，现为 57.92）。列为第 3 轮改动。

D

M3

做了什么

T7 取 M-C-I 未进 M0、接近阈值的 SAM 提议，按软接受分排序、掩码 NMS 后每图前 20 个。每个候选（未被当前掩码覆盖时）：T2 → T3（1 次调用）→ P(yes) ≥ τ_B 则 T5：Qwen 在近景里画框（1 次调用）→ SAM 用框在 T1、T2 各分割一次取并集加入掩码；框不可用时退回候选掩码。

得到了什么结果

  • B 的判别力强：候选中 20% 是真漏检，P(yes) 区分它们的 AUC 0.94。
  • 画框 3,839 次全部可解析（失败率 0%），但对真漏检候选，框 + SAM 并集与真值的 IoU 平均 0.13，低于候选掩码本身的 0.22；只有 28% 的情况框更好。
  • τ_B < 0.8 时补入都让验证集变差；选中 0.95。验证集 B 相对 A +0.26 / +0.23 / +0.01；测试集 +0.07 / −3.03 / −3.15。

遇到的关键问题

反常排查（与 Codex 一起）：测试集的骤降主要来自 test_96 的一次调用。候选外接框 180×286，4 倍近景就是整图；Qwen 回答 [0,0,1000,1000]，SAM 用整图框新增 972,791 像素，其中 972,774 是误检，占 B 新增误检的 81%。只撤销这一步，B 仍比 A 低 0.10（其余补入像素精度 24%）。验证集里也有 4 次整框，但都在小近景上。B 的“判断”强、“生成掩码”弱。

下一步怎么做，为什么

第 2 轮去掉 T5：核实通过后直接加入候选掩码（验证集最终 F1：k=20 +0.72，k=50 +1.97）。

E

M4

做了什么

对 B 之后的每个连通域，用外接框提示 SAM（T1、T2 各一次，取与原域 IoU 高者），IoU(新,旧) ≥ 门限才替换；所有替换一次性合并，与访问顺序无关。门限在验证集上选，含“不修”和“总是替换”。

得到了什么结果

  • 验证集：总是替换会掉 0.5；门限 0.7–0.8 时 +0.2。选中 0.8 / 0.8 / 0.7。
  • 测试集 C 相对 B：+0.17 / +0.41 / +0.49。
  • 代价：CPU 上每图约 11 秒。

遇到的关键问题

新旧 IoU 门限只限制形状变化、不判断对错：test_96 上 C 接受了与错误大区域 IoU 0.89 的替换。测试集 k=20 的 C 让像素指标上升，整目标误检率却从 40.0% 升到 41.8%（连通域被拆分或合并）。

下一步怎么做，为什么

本轮不改 C；之后考虑只修 A 核实为“是”的连通域。
